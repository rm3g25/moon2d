# Level objects: static objects, dynamics, events

What a level carries besides tiles and monsters: the static objects
(`objects`), the dynamic objects (`dynamics`, `Levels.Dynamics`) and the
events of the level from JSON. The 3.0 release plan that set the series
off is the first entry of the journal. The kinds of dynamics with a
design of their own have files of their own: `smoke.md`, `fans.md`,
`graph.md`, `lightning.md`, `sky.md`.

## Journal

### Сессия: события уровня из JSON, v3.0.10 (2026-09-29)

Первые события в игре. Повод: подсказка медлаба (экран 12) печаталась
посреди боя с танками, а hintHoldWhileAlive только морозил ей таймер.
Нужно было другое - не показывать, пока охрана жива, - и это уже условие,
а не удержание. Заодно задел на уровни 3+: взрыв, спавн, любая сцена по
триггеру.

#### Решения (аргументы в скобках)
- Событие = экран + условие + задержка + список действий, три независимых
  слоя (условие не знает о действиях, задержка - общий модификатор, а не
  свойство allDead: "вошёл на экран, через две секунды музыка" пишется
  сразу). Отдельная секция events в JSON, старые triggers на сущностях не
  тронуты - миграция потом или никогда.
- Кого ждём - метки на расстановках (`"tag": "labGuard"`), не тип
  монстра: из шести тел экрана 12 вниз к герою приходят четыре (два
  танка, бетонер над дырой x=12, самка грейвела - она без проверки края
  и спрыгивает; самец x=15 и два бетонера остаются наверху). По типу это
  не выразить, по метке - решает автор уровня.
- Условия опрашиваются каждый тик (как HintHeld раньше), а не приходят
  событиями meDied: труп остаётся трупом, опрос не теряет ничего, и
  условие - это предикат над состоянием, а не бухгалтерия подписок.
- Задержка идёт, пока условие держится; сбой условия начинает отсчёт
  заново. Над трупом героя директор не тикает: рестарт всё равно взводит
  экран заново (ReArm рядом с перевзводом триггеров).
- Модель и парсер - в Core (`Levels.Events`, редактор будет их писать),
  исполнитель - в `Game/Events/` (место было обещано при раскладке).
  Директор получает доску сообщений и колбэк музыки - как хеншин получает
  сцену и CureHero; поле монстров приходит с каждым тиком, потому что
  рестарт рождает его заново.
- Музыка: `ChangeMusic` в dpr - один метод для триггеров и событий
  (играет и запоминает трек для рестарта), вместо второй копии трёх строк.
  `TickerNoticeTicks` переехал в Hud.Messages к BigMessageTicks - директору
  нужна длительность, до dpr ему не дотянуться.
- Опечатки умирают на загрузке: неизвестное условие или действие,
  событие без id или без действий, allDead без тега, экран вне списка,
  тег, которого не носит ни одна расстановка (такое сработало бы сразу -
  держать некому).
- hintHoldWhileAlive снесён вторым коммитом (единственный пользователь -
  медлаб; вместе с THintHold, HintHeld, HoldTerminal, Held терминала,
  AnyAliveOnScreenOf). Удержание как механизм не бесполезно, но без
  клиента - код в стол.
- Расширение проверяется ценой следующего события, а не лишним кодом
  сейчас: условие - член перечисления + слово в EventConditionIds +
  ветка ConditionHolds; действие - то же с EventActionIds и Play.
  Пока условий два, ConditionHolds - if; с третьим станет case.

#### Грабли сессии
- В `{ }`-шапке юнита нельзя приводить JSON: первая же `}` закрывает
  комментарий, дальше компилятор читает JSON как Паскаль (50 ошибок из
  одной). Пример JSON - в `//`-комментарии над записью.
- `Game\Events\` на два уровня ниже корня: `{$I ..\..\Moon2D.inc}`.

#### Открытое
- Кандидаты в следующие условия/действия, когда появится клиент: heroAt
  (область экрана), afterEvent (цепочки), spawn, explode (веер + звук +
  тряска), swapSprite. Не раньше уровня, которому это нужно.

#### Коммиты
Add level events from level JSON (3.0.10); Remove the hint hold; the
events replace it; Update the docs for level events. Тег 3.0.10 - на
последнем.

### Сессия: план релиза 3.0 - объекты и эффекты (2026-09-30, план, кода нет)

Повод: заставка и меню стали чёткими и живыми, игровой мир рядом с ними -
мыло 2008 года. Полная перерисовка арта отложена (фаза 3, после
редактора), но дешёвый и серьёзный апгрейд играбельности есть: HD-задники,
статические объекты, живые эффекты. Состав и граница релиза - в стратегии
("РЕЛИЗ 3.0 - ГРАНИЦА И СОСТАВ"), здесь - решения по коду и данным, чтобы
в следующем чате "делаем" значило одно и то же.

#### Решения (аргументы в скобках)
- Объекты - дополнение к тайлам, не замена: уровень может стоять целиком
  на объектах, целиком на тайлах или на обоих, одно другого не отменяет
  (уровни 1-2 живут на тайлах; объекты - это ровно то направление,
  которое выбрано для текстур будущих уровней: сетка коллизий + объекты
  сверху, так что слой объектов - первая половина будущей модели уровня,
  и редактор получит её готовой).
- Объект = спрайт произвольной формы в произвольной точке экрана, без
  коллизий (коллизии остаются за сеткой; корабль вместо шаттла - вид, по
  нему бегают по тайлам под ним, как сейчас по шаттлу в заднике).
- Динамические эффекты НЕ привязаны к статическим объектам (маячок
  ставится куда угодно теми же координатами; дым - просто текстура в
  точке; прицеплять к объекту нечего - объекты не двигаются до вагонов
  уровня 4).
- Каждый переиспользуемый динамический объект - свой юнит со своими
  свойствами (у маячка и дыма разные "боссы": маячок переписывают, когда
  захотелось строб, дым - когда захотелось ветер).
- Родитель по образцу VCL, но только система координат: Parent = nil -
  прибит к экрану гвоздями, Parent = монстр (по тегу) или герой - едет за
  ним. Владения и времени жизни родитель НЕ несёт (дым босса должен
  висеть над воронкой после взрыва, а не умирать с боссом в тот же кадр).
- Ссылку на монстра не хранить: якорь держит тег и каждый тик спрашивает
  поле, где монстр; "нет такого" - эффект остаётся на последней позиции
  и дотлевает (ни висячих указателей, ни `if Assigned`; поле монстров
  рождается заново на рестарте - как у директора событий).
- Эффекты - абстрактный класс TLevelEffect, не интерфейс (эффекты лежат в
  TObjectList, он владелец; интерфейс тащит refcount - два хозяина у
  одного объекта; тот же приём, что THealthHud/TScoreHud/TGameApp: игра
  держит базовый тип и не спрашивает, кто внутри; вид известен только на
  границе JSON, где строка kind становится вызовом конструктора).
- TMonster интерфейса не получает (TObjectList + refcount = монстр
  освобождён, список держит труп; классика, не лечится - обходится тегом).
- Вспышки героя - не объекты и не юниты, а пресеты эмиттера (залп, потом
  тление); живут там, где их зовут: Game.Henshin и кластер возрождения в
  dpr (модуль под пресет - класс в плаще).
  (Отменено в 3.0.47: см. сессию про покров героя.)
- Эмиттер - один на всех: искры логотипа, дым и маячки уровня, эффекты
  героя (один механизм, четыре клиента; синий костёр льда рифмуется с
  костром на логотипе - меню и игра начинают говорить на одном языке).
- Задники уровня 1 в HD и без вклеенных корабля/спутника (генерируются
  за минуты, суть не меняется; под 16:9 позже переделываются так же).

#### Эмиттер (шаг 1, рефакторинг без бампа)
Menu.Embers - не общий эмиттер: сиды берутся из контура букв (альфа
текстуры, нормали к воздуху). Общее в нём - жизнь частицы: рождение,
полёт со сносом (lift), остывание цвета, затухание, перерождение. Это и
выделяется в Core/Effects.Emitter; источник рождения - параметр:
- контур (сиды с нормалями - остаётся в Menu.Embers как поставщик сидов);
- точка (дым, маячок-искры, вспышки);
- отрезок (след героя: точки между позицией прошлого и этого тика).
Параметры частицы: стартовая скорость и разброс, снос, время жизни,
размер, цвет от -> до, blend. Два способа рисовать: точечное свечение
через Render.Glow (искры, маячки - аддитивно) и спрайт (клуб дыма -
обычная альфа). Проверка шага: костёр над логотипом не изменился.

#### Объекты уровня (шаг 2)
- Core/Levels.Objects - модель и парсер (редактор будет писать):
  ```
  "objects": [
    {"sprite": "level1-objects:ship", "screen": 1, "x": 0, "y": 224,
     "layer": "behindTiles", "tag": "ship"}
  ]
  ```
  x/y - юниты экрана (не кадра: широкий кадр их не тронет, Game.Space
  для того и разведён); layer - behindTiles / aboveTiles; tag -
  необязательный, тот же словарь, что у расстановок и событий.
- Core/Render.Objects - рисует объекты экрана для слоя (по образцу
  Render.Tiles: DrawBackground / DrawTiles, отдельные вызовы, чтобы
  слои трясти по-разному). Свой TSpriteCache с DisableColorKey и честные
  PNG с альфой (иллюминаторы корабля и тень спутника - чёрные, через
  color key они бы пропали; на светлом задке незаметно, на первом тёмном
  - сразу). Набор по конвенции `<assetsDir>-objects.mset`, как
  `-backdrops`, в spriteSets не объявляется.
- Порядок слоёв в TMoonGame.Render: задник (NoShake) - объекты за
  тайлами (scWorld) - тайлы - объекты перед тайлами - пули - монстры -
  герой - эффекты (канал якоря) - курсор и HUD (NoShake).
- Плотность пикселей: корабль рисовать в плотности задника, не тайлов
  (он по сути кусок задника, который научился двигаться; три плотности в
  кадре уже есть - HD-задник, 64 px тайлы, 32 px спрайты, - четвёртая
  лишняя).
- Спутник вынимается из задника - задник последних экранов перерисовать
  без него, иначе два спутника.

#### Эффекты уровня (шаг 3)
- Раскладка юнитов, по одному на эффект, целиком в Core (не модель в Core
  + рантайм в Game, как у событий: события рисовать не надо, эффекты -
  надо, и редактору тоже - превью уровня с мёртвыми маячками не превью;
  рисование и так на Render.*, а это Core):
  - Core/Effects.Defs - TEffectPlacement (screen, x, y, tag, parent - один
    раз, а не копией в каждом def: иначе четыре записи с полями
    Screen/X/Y, prefix test размазанный по файлам), TEffectKind + ids,
    TLevelEffect (Tick / Draw(renderer, alpha) / Finished - для залпов;
    маячок не кончается никогда);
  - Core/Effects.Anchor - TEffectAnchor с TryFollow(out point): Boolean
    и TScreenAnchor; якоря к монстру и герою - в Game (им нужны
    TMonsterField и THero);
  - Core/Effects.Beacon - TBeaconDef + парсер + TBeacon;
  - Core/Effects.Smoke - TSmokeDef + парсер + TSmoke;
  - Game/Effects/Effects.Field - владелец TObjectList<TLevelEffect>,
    диспетчер kind -> конструктор, TMonsterAnchor/THeroAnchor, тик и
    отрисовка по слоям, перевзвод на рестарте (рядом с ReArm директора).
- JSON:
  ```
  "effects": [
    {"kind": "beacon", "screen": 1, "x": 96, "y": 208,
     "color": "#ff2020", "brightness": 0.8, "hz": 1.0, "pattern": "strobe"},
    {"kind": "smoke", "screen": 15, "x": 300, "y": 96,
     "sprite": "fx:puff", "rate": 4, "drift": -0.4, "life": 60},
    {"kind": "smoke", "id": "bossSmoke", "parent": "boss", "x": 0, "y": -12,
     "sleeping": true, ...}
  ]
  ```
  parent - тег расстановки или слово hero; при parent x/y - смещение от
  родителя. Строка kind декодируется в enum один раз на границе, дальше
  `case`. Новый эффект = новый юнит + ветка в case. Опечатки умирают на
  загрузке, как у событий (неизвестный kind, экран вне списка, parent,
  которого не носит ни одна расстановка).
- Маячок (Beacon, заградительный огонь): цвет, яркость, частота, характер
  - pulse (синус), strobe (короткая вспышка, долгая пауза - авиационный),
  faulty (дрожь на TXorShift; `Random` не трогать - он кормит таблицу
  спавна босса). Рисуется DrawGlow: цвет - tint, яркость * f(t) - level;
  блик - gsFlare на пике вспышки. Render.Glow это уже умеет, нового
  почти нет.
- Дым (Smoke): спрайт клуба (PNG с альфой; чёрный в клубе - сажа, не
  прозрачность), частота рождения, дрейф вверх, время жизни, лёгкая качка
  вбок, затухание альфы - всё параметры эмиттера с источником "точка",
  blend обычный. Не аддитивный (иначе дым светится, как радиоактивный:
  на Луне канон, но не везде).
- Тряска: эффект с родителем-монстром едет по каналу scMonsters, с
  героем - scHero, прибитый к экрану - scWorld (иначе дым босса дрожит
  не в такт с боссом).
- Действие события startEffect (id): будит эффект с "sleeping": true.
  Клиент - дым босса первого уровня перед смертью: условие - порог
  здоровья босса (ProcessBossThresholds уже знает момент; нужно новое
  условие события или прямой вызов из порога - решить на месте). Два
  механизма, построенные порознь (события 3.0.10 и эффекты), впервые
  встречаются.

#### Эффекты героя (шаг 4, пресеты эмиттера)
(Отменено в 3.0.47: вместо пресетов эмиттера - модуль Game.Shroud, см.
сессию про покров героя. Раздел оставлен как запись замысла.)
- Возрождение (Revive, HandlePitFall) и первое появление в уровне

- Ледяная форма: пока form = hfIce, эмиттер идёт за героем с малой

- Владелец эмиттера героя - TMoonGame; рисуется на канале scHero.

### Сессия: статические объекты уровня, v3.0.12 (2026-09-30)

Шаг 2 релиза 3.0, сделан раньше эмиттера (шаг 1): объекты от него не
зависят, а экран 1 без шаттла стоял пустым с 3.0.11. Корабль и спутник
вынуты из задников 2008 в слой объектов; код не знает, что именно рисует.

#### Решения (аргументы в скобках)
- Место объекта - `x`, `y` левого верхнего угла и `width`, всё в единицах
  экрана; высота из пропорций арта. (Клетка 32 - шаг 11 px на 1080p,
  опоры корабля на пол так не поставить; полный прямоугольник даёт
  независимые w и h, и одна опечатка сплющивает арт. Ширина в единицах не
  зависит от плотности картинки: перерисованный в другом разрешении
  корабль остаётся на месте.)
- Яркость - тот же `"tint": [r, g, b]`, что у задников, тот же парсер;
  три равных числа - чистая яркость. (Одно слово для одной вещи во всём
  JSON уровня; синий сдвиг ночи задникам уже понадобился.)
  `TBackdropTint` стал `TColorTint`, `ReadBackdropTint` - `ReadTint`:
  старые имена врали бы про объекты.
- Модель - в Levels.Defs (`TLevelObject`, `ParseObjects`, свойство
  `Objects`), а не отдельным юнитом Levels.Objects, как было в плане.
  (Объекту нужны ридер тинта и ELevelError из Levels.Defs, а Levels.Defs
  владеет списком - отдельный юнит потребовал бы третий юнит под тинт;
  машинерии вышло бы больше, чем самих объектов: запись и один метод.)
- Отрисовка - свой юнит Core/Render.Objects (`TObjectScreenRenderer`), как
  в плане. Все спрайты разрешаются в конструкторе (опечатка в имени
  падает на загрузке уровня, а не на экране 14).
- Пересчёт процентов в color mod вынесен в `Render.Sprites.TintTexture`
  (задники и объекты - два клиента одной формулы).
- Соглашение `<assetsDir>-<вид>.mset` - в одном месте, `OpenLevelArtSet` в
  dpr (у задников появился второй клиент). Набор объектов открывается,
  только если уровень что-то ставит (уровню без объектов пустой набор не
  нужен).
- Слой - между задником и тайлами, канал тряски scWorld. (Корабль стоит
  на полу из тайлов; неподвижный над трясущимся полом он бы парил.)
- `layer` и `tag` из плана не сделаны. (Клиентов нет: корабль и спутник

### Сессия: динамические объекты, маячок, v3.0.13 (2026-09-30)

Первая половина шага 3 релиза 3.0, опять раньше эмиттера (шаг 1): маячку
частицы не нужны, он рисуется светом Render.Glow. Динамический объект -
то, что расставляется как статический объект, но живёт от тика к тику.
Три лампы: синяя на киле корабля (экран 1 уровня 1), красная барахлящая
на антенне спутника (14-17 уровня 1), та же умирающая на экране 1
уровня 2.

#### Решения (аргументы в скобках)
- Один абстрактный предок `TDynamicObject`, и ВСЕ виды - в одном юните
  `Core/Levels.Dynamics`, вместе с парсером. Переопределяет план релиза
  (там был юнит на эффект). Новый вид - класс, слово в `DynamicKindIds`
  и ветка в `CreateDynamic`.
- Предок держит и читает общее - `screen` или `parent`, `x`, `y`, `tint`
  (как у статики) - и сам прибавляет смещение к началу отсчёта: наследник
  получает в `DrawAt` готовую точку и знает только свои свойства, `Tick` и
  отрисовку.
- Родитель по образцу VCL, только система координат: без родителя объект
  прибит к точке экрана (`screen` обязателен), с родителем x/y считаются от
  левого верхнего угла родителя, а `screen` запрещён - экран решает
  родитель. Объект показывается везде, где стоит родитель (спутник на
  14-17 - одна картинка, и лампа едет с ним).
- Родитель пока - только статический объект по тегу: у объектов появилось
  поле `tag`. Монстр и герой как родители - вместе с дымом.
- Где стоит объект, решает `Render.Dynamics` (`TDynamicScreenRenderer`) один
  раз при загрузке: статические объекты не двигаются. Двинется родитель -
  стоянка станет запросом на каждую отрисовку там же; предок и виды этого
  не заметят.
- Секция JSON - `"dynamics"`, не `"effects"` из плана (Земля в небе - не
  эффект, а тоже динамический объект).
- Слой - сразу после статических объектов, до тайлов, канал тряски scWorld
  (лампа на корабле гаснет за героем, проходящим мимо).
- Лампы тикают на любом экране и переживают рестарт: владелец - `TLevel`,
  уровень при смерти не перечитывается (вернулся - лампа в середине ритма,
  а не с начала).
- Тинт маячка - цвет света: белая текстура свечения, тинт в процентах
  через `PercentToColorMod` (стал публичным в Render.Sprites) - то же
  слово, что у задников и объектов.
- Маячок из четырёх слоёв: горячее ядро (тинт с примесью белого), ореол,
  засвет вокруг (света на окружающее), на пике - блик с четырьмя шипами
  (`glint`); между вспышками стекло тлеет на 8% (лампа, а не дырка).
- Режимы `blink`: steady, pulse, flash (резкий фронт, экспоненциальный
  спад), double, faulty (цикл на 8 слотов: держит / проседает / гаснет),
  dying (на каждом цикле новая тусклая яркость 5-40%, частота 14 -
  мельтешение садящейся батарейки). Частота - в секунду игрового времени
  (авиационная норма заградительных огней 40-100 вспышек в минуту).
- Случайность faulty и dying - `SlotRoll`: свой `TXorShift` от номера слота
  и сида (`Random` не трогаем - он кормит таблицу спавна босса). Чистая
  функция номера: кадр между тиками не спорит с тиком. Сид - позиция в
  десятых юнита, лампы в разных точках барахлят вразнобой.
- Лучи старбёрста - два свойства: `rays` (длина луча от центра, 0 = нет) и
  `rayIntensity`. Новая форма `gsStarburst` в Render.Glow: крест тоньше шипов
  флейра и медленнее гаснет, текстура 256 px (волосу нужны пиксели поперёк).
  В покое луч держит 60% длины, вспышка дотягивает его до полной.
- На спутнике `glint` обнулён: два креста на одной лампе спорят.

#### Попутно
- `TColorTint` и `ReadTint` уехали из Levels.Defs в свой юнит
  `Core/Levels.Tint` (Levels.Defs использует Levels.Dynamics, тинт нужен
  обоим - без выноса цикл юнитов). Ошибка формы тинта - теперь
  `ETintError`, не `ELevelError`.
- У `TLevel` появился деструктор - владелец списка динамических объектов.
- Проверки на загрузке (`CheckDynamics`): прибитый объект вне списка
  экранов, тег родителя, которого не носит ни один объект, два объекта с
  одним тегом на одном экране.

#### Находки
- Купол на киле корабля нарисован красным стеклом; синяя вспышка поверх
  него на пике уходит в бело-голубой.
- Кода без компилятора: прочитан отдельным агентом как компилятор, ошибок
  сборки не нашлось; замечания по комментариям и `const` исправлены.

#### Открытое
- Коэффициенты (засвет, ядро, блик, лучи, частоты) подобраны в
  симуляции на Python - подкрутить вживую.
- Дым (Smoke) - на эмиттере шага 1, с родителем-монстром по тегу и
  действием события startEffect.
- Земля (`globe`) - тонкий наследник в Levels.Dynamics, рисование в
  Core/Render.Globe (вынос Menu.Globe) - принято.

#### Коммиты
Add dynamic objects with a beacon (3.0.13); Hang beacons on the level 1
and 2 satellites and the ship; Update the docs for dynamic objects. Тег
3.0.13 - на последнем.

### Сессия: общий арт объектов, v3.0.17 (2026-10-01)

Земля с огнями (~870 КБ) и спутник лежали копиями в наборах обоих
уровней, и каждый следующий уровень с Землёй добавил бы ещё копию.
Причина была не техническая - соглашение "у уровня ровно один набор
объектов, по имени, без списка".

#### Решения
- Общий арт объявляется, как тайлы: `"objectSets": ["sky"]` в JSON
  уровня (`TLevel.ObjectSets`). Ищется после собственного набора
  объектов уровня, в порядке объявления. Набор - оглавление плюс
  картинки, читаемые по смещению, так что уровень платит только за то,
  что рисует.
- Собственный `<assetsDir>-objects` стал необязательным: открывается,
  если файл есть. (Раньше - если уровень ставит объекты; теперь объекты
  могут целиком жить в общих наборах.) Объявленный общий набор, которого
  нет, - ошибка загрузки, как у тайлов.
- `sky.mset`: `earth`, `earth-night`, `satellite`. `level1-objects` -
  только корабль, `level2-objects` удалён.
- Динамике отдаётся кэш арта объектов, а не один набор
  (`TDynamicCanvas.Art: TSpriteCache`): карты глобуса разрешаются по тем
  же правилам, что спрайты объектов, `sky:earth` тоже работает. Для этого
  разрешение имени вынесено из `TSpriteCache.Get` в `SourceOf`. Ночная
  карта обязана лежать в одном наборе с дневной (`TGlobe` читает из
  одного) - иначе ошибка загрузки.
- `NeedsArt` / `AnyNeedsArt` удалены - решать, открывать ли набор, больше
  нечему.
- В dpr открытие набора по имени вынесено в `OpenSpriteSet`, им пользуются
  и тайлы, и общий арт, и `OpenLevelArtSet`.

#### Находки
- Квалификатор `набор:имя` не работал никогда: на Windows ExtractFileName
  режет и по ':' (как по букве диска), и `common:pustota` превращалось в
  голое `pustota`. Уровень 2 спасало то, что первый набор с `pustota` -
  как раз `common`. Теперь имя делится по ':' до отрезания пути; картинка
  уровня 2 не меняется (проверено по манифестам). Нашёл агент-ревьюер.

#### Открытое
- Скрипт релиза (вне репозитория) должен подхватить новый `sky.mset` и не
  ждать `level2-objects.mset`.
- Проверки неоднозначности (`AmbiguousNames`), как у тайлов, для кэша
  объектов нет - пока наборов два и имена разные.

#### Коммиты
Share object art between levels (3.0.17); Move the sky art into a shared
set; Update the docs for shared object art. Тег 3.0.17 - на последнем.
