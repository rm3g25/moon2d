# Moon 2D Remake - передаточная записка (3.0.x: доводка после ухода режима 2008)

Статус на 2026-09-29: **3.0.10 - события уровня из JSON.** В level*.json
появилась секция events: условие (enterScreen, allDead по тегу расстановок),
задержка, действия (bigMessage, smallMessage, hint, music). Модель и парсер -
Core/Levels.Events, исполнитель - Game/Events/Events.Director. Подсказка
медлаба выходит через секунду после гибели четырёх labGuard, а не посреди
боя; hintHoldWhileAlive снят. Подробности - в сессии "события уровня из
JSON" внизу. До этого 3.0.9 - настройки игрока отдельно: выбор игрока
(сложность, язык, полный экран - он теперь запоминается) пишется в
%APPDATA%\Moon2D\settings.json и перекрывает bin\config.json по ключам;
config.json игра больше не пишет, в поставке vsync включён. До этого 3.0.8 -
терминал связи. Бегущая строка ушла:
подсказки уровня печатаются по буквам в рамке под кардиомонитором, текст
перед уровнем - так же, на подложке поверх неба. После тега юниты разложены по

## Архитектура (юниты)

Юниты лежат в папках Core/, Game/, Hud/, Menu/ (с раскладки после 3.0.8);
какой юнит где и правило слоёв - в CODEBASE-MAP, раздел "Раскладка
исходников". Таблица ниже - про ответственность, не про пути.

| Юнит | Ответственность |
|---|---|
| Moon2D.dpr | Композиция: конфиг → реестр → уровень → SDL-хост → игра. TMoonGame: state-каркас (gsPlaying), коллизии пуль, контакты, чекпоинты, события монстров, гравел-трайл, бонус-слот, CreateHud - угловые HUD и ряды над фигурами заново на каждый уровень; церемония - через FHenshin |
| Sdl2.Core | Минимальные SDL2-биндинги (окно/рендер/события/мышь/текстуры) |
| Game.Loop | TGameHost + fixed timestep (Gaffer), TGameApp-база |
| Game.Config | config.json; tickRate=33 — РЕАЛЬНАЯ частота ориг. WM_Timer(20мс) на живой Windows |
| Render.Sprites | Кэш BMP→текстур (color key чёрный), TileSize=32 ЮНИТА vs TileArtSize=64 ПИКСЕЛЯ — не путать |
| Levels.Defs | level*.json: тайлы+коллизии (SolidAt), фоны, сущности с overrides/triggers и тегом, события (Events; CheckEvents отказывает событию с чужим экраном или тегом без носителя) |
| Levels.Events | Секция events уровня: TLevelEvent (экран, условие enterScreen/allDead, тег, задержка, действия bigMessage/smallMessage/hint/music), словари условий и действий константами, ParseLevelEvents. Модель и парсер, без логики |
| Events.Director | TEventDirector - исполняет события на живой игре: Tick(экран, поле) проверяет условия несработавших событий экрана, отсчитывает задержку, играет действия один раз; ReArm(экран) на рестарт; музыка через колбэк ChangeMusic игры. Рождается с уровнем |
| Render.Tiles | Фон задником + тайлы 64-кроп в клетку; DrawBackground/DrawTiles наружу - тряска двигает их порознь |

| Hud.Vitals | Здоровье: THudVitals - кардиомонитор (ряд 5 ячеек нормы + салатовый бонус за чертой, пульс по здоровью) |
| Hud.Charge | Очки: THudCharge - заряд бонуса до 50, значок ждущей награды, ряд серии из 10 |
| Hud.Marks | Ряды здоровья над фигурами: у героя грамматика монитора (норма/контуры/бонус за чертой), у монстра 6 ячеек - по паре на треть, цвет по третям прицела; показ после изменения, тает; едут по каналам тряски фигур |
| Game.Bonus | TBonusKind + BonusCost=50 - общий словарь рулетки для игры и HUD |
| Game.Henshin | THenshin - церемония трансформации одним автоматом: отсчёт 3..2..1, пять волн, вспышка, костюм надеть (Finish) и снять (RemoveIceForm), Reset на рестарт. ## Ключевые константы координатной системы
- Логика: 512×384 игровых юнита (SetMaxC оригинала), клетка 32, герой/монстр 32
- Тайловый АРТ 64×64 px (кроп верхнего левого), рисуется в клетку 32 юнита
- Y — линия НОГ; хитбоксы пуль/контактов — ВНИЗ от Y (y..y+32); тела рисуются ВВЕРХ (y-32..y)
  ⚠️ ГЛАВНАЯ ЛОВУШКА ПОРТА: у джуна ДВЕ версии каждого оракула (герой/монстр)
  с разными знаками (герой щупает пол y−3, монстр y+3). Не переиспользовать!

## Осознанные отступления от 2008
1. RoundHalfUp кадров анимации (банковское округление хромало и в оригинале)
2. Труп подчиняется гравитации + одноразовая посадка (в ориг. висел в воздухе)
3. Прицел: DX=9 DY=10 — калибровка игроком по живому экрану (NumPad-тюнер)
4. Лечение до 10 (ориг. 15), договорённость
5. Телепорты роняют героя (SetY→haFall) — нет стояния на воздухе
6. Смерть возрождает на чекпоинте текущего экрана, мир перерождается
   (2008: смерть = меню; чекпоинт служил только лункам) — часть 5.1
7. Колонка пунктов меню снова 17, как в 2008 (3.0.3): отступление 15 от
   2026-07-21 держалось только ради DIFFICULTY:NORMAL, а грейд теперь
   ячейками, не словом. Заголовок экрана ушёл с колонки 24 / ряда 1 на
   левый край колонки пунктов, по вертикали на середину флагов
8. Тряска экрана на взрывах и хеншине (авторское нововведение 2026, в
   оригинале не было) - см. сессию 2026-09-26. Чисто визуальная: ни одна
   формула 2008 не тронута
9. HUD здоровья: кардиомонитор примитивами вместо кругалей heroes\health.bmp
   (2.5.0). Норма 5 на всех сложностях, hard/wild стартуют ранеными по
   пустым контурам; бонус выше 5 - салатовые ячейки за чертой. С 3.0.0
   кругалей нет вовсе (в 2.5.x их возвращал режим 2008)
10. Дорожки текста ушли вниз: бегущая строка 40, тикер 52 (было 24/36) -
    монитор выше иконок. С 3.0.8 на дорожке 40 - рамка терминала, бегущей
    строки нет (п. 17)
11. HUD очков: заряд бонуса примитивами вместо "Score: N" (2.5.2), плюс
    серия убийств видна рядом из 10 ячеек. С 3.0.0 "Score: N" нет вовсе
12. Оплата бонуса перенесена с выпадения на активацию (2.5.2): счёт держится
    на 50+ пока награда ждёт, минус 50 по правой кнопке; следующая награда
    выпадает сразу, если осталось ≥ 50. Итоговая арифметика та же, другое
    только число на экране
13. Подпись лого: "Computer Dragon 2008-2026" (2008 - дословная line2;
    "2DGames Software 2008 - 2026" жило до 3.0.3) - подпись автора,
    решение автора. Credits переписаны той же строкой: "Computer Dragon
    presents", авторы как в 2008, плюс "Released in 2008, remade in 2026";
    портал 2DGames.ru ушёл (строка и не влезала: 42 крупных глифа = 562
    юнита)
14. Ряды здоровья над героем и монстрами (2.5.3): нововведение ремейка,
    как кардиомонитор; с 3.0.0 показываются всегда. Чисто визуально, ни
    одна формула не тронута; трети прицела переехали в TMonster.HealthTier
    без изменения чисел
15. Сложность в меню (3.0.3): клик по пункту листает грейд по кругу на
    месте, подменю 2008 (три строки + назад) снято; грейд показан тремя
    ячейками здоровья рядом с подписью, название и "с рестарта или нового
    уровня" - мелкой строкой под меню, пока курсор на пункте. Значение и
    сохранение в config.json - как были
16. Небо меню (3.0.3): вместо sky.bmp 512x512 + fullmoon.bmp + 10 спрайтов
    звёзд - туманность 16:9 с обрезкой по кадру, звёзды и луна кодом
    (Menu.Starfield, Menu.Globe). Дрейф луны по диагонали - дословно 2008,
    сама луна - глобус. Логотип без нарисованного свечения: ореол и угли
    считаются из его альфы (Menu.Logo, Menu.Embers). Вход в подменю -
    наезд: планы растут от центра на 4/8/14/20% за 0.8 с, назад тем же
    путём. Чисто визуально
17. Терминал связи вместо бегущей строки (3.0.8): hintText печатается по
    буквам в рамке под монитором и держится на чтение, а не ползёт справа
    налево; тикер съезжает под рамку. Текст перед уровнем печатается тем
    же ходом на подложке поверх неба (2008 выводил его готовым блоком),
    первая клавиша допечатывает, вторая начинает уровень. Подсказки двух
    экранов level1 переставлены: TEK-R1 - на экран 16, перед дверью;
    медлаб ждал двух танков (hintHoldWhileAlive; снято в 3.0.10, см. 18)
18. События уровня из JSON (3.0.10): секция events в level*.json - экран,
    условие (enterScreen, allDead по тегу расстановок), задержка в тиках,
    список действий (bigMessage, smallMessage, hint, music). Levels.Events -
    модель и парсер (Core, редактор будет их писать), Events.Director -
    исполнитель (Game/Events). Подсказка медлаба - первое событие: четыре
    labGuard (два танка, бетонер над дырой, самка грейвела) мертвы -
    через секунду печатается текст

## Дебаг (под {$DEFINE DEBUGKEYS}, выключить для релиза)
PgUp/PgDn — экраны, T — инспектор тайла под курсором, NumPad 4/6/8/2 —
тюнер прицела, M — вкл/выкл всю музыку (звуки остаются; для съёмки
трейлера под наложение своего трека). Реализация: Mix_VolumeMusic(0/128)
— глушится канал микшера, игра под капотом продолжает менять треки по
триггерам, размут возвращает актуальный трек экрана без бухгалтерии.
Громкость музыки — глобальное состояние микшера, переживает
Halt/Load/Play.

## Сессия: миграция BMP → PNG, v2.2.0 (2026-08-02)

Формат наборов спрайтов (.mset) отложен: сперва вся графика
переезжает на PNG, чтобы формат родился с одним типом картинок внутри и
не тащил версионирование с первого дня.

### Шаг 1 — конвертация (tools/bmp2png/convert.py)

Все 471 BMP получили PNG-близнеца. Правило прозрачности снято с кода
(grep по SetColorKey), а не придумано, но по ходу работы трижды
переписывалось — исходники оказались грязнее, чем ожидалось.

**Классы файлов:**
- **alpha** (447): textures\, heroes\, weapon\, monsters\, Stars\ — их
  кэши держат color key по ТОЧНОМУ чёрному (0,0,0).
- **opaque** (24): levels\* (DisableColorKey), 8 корневых файлов и 9
  крашеных тайлов (см. ниже). Корневые НЕ запекаются сознательно: их
  прозрачность делает рантаймный цитатный код 2008 (пороги <33 / <15,
  альфа 130 логотипа, порог атласа шрифта). Запечь = сломать цитату.

**Финальное правило для alpha-класса.** Прозрачным становится пиксель,
если он чистый чёрный ИЛИ входит в почти-чёрную (макс. канал ≤ 16)
область, дотянувшуюся до края кадра, И эта область прошла один из двух
тестов:
- **тонкая** — исчезает при эрозии 3×3, то есть толщиной ≤ 2 px. Это
  бахрома от ресайза, нарисованной фигурой быть не может;
- **плоская** — один точный цвет покрывает ≥ 50% области, и этот же цвет
  сидит на рамке кадра. Это крашеная заливка фона.

Всё прочее — арт, не трогаем. Разделение проверено на данных и оказалось
не пограничным: заливка идёт 71–100% одного цвета, а ноги гравела —
5–13% доминирующего цвета на 40–100 оттенков.

**Почему потребовался тест на толщину.** Первая версия просто заливала
от края всё почти-чёрное — и съедала ноги гравела: они тёмные, толстые и
касаются фона. Тест эрозией отделяет нарисованную фигуру от бахромы.

**Крашеные тайлы → opaque целиком.** Если заливка занимает ≥ 25% кадра,
файл сохраняется непрозрачным без альфы вовсе. Ключевое наблюдение:
цвет заливки (12,12,11) игра НИКОГДА не выбивала — ключ по чистому
чёрному, — значит эти тайлы все 20 лет рисовались сплошными, такими их и
задумывали. Выбить их = пустить фон насквозь (глюк на 2 уровне при
плейтесте). Правило сработало ровно на 9 файлах: lamp, provod1..6, оба
pustota — лампы, трубы и «пустота», то есть закрывающие плитки.

**Итог:** убрано 873 857 px чистого чёрного + 26 677 px бахромы +
32 148 px заливок; 16 872 px тёмного арта сохранено (ноги и подобное).
Инвариант проверен машинно на всех файлах: цвета выживших пикселей не
изменены ни в одном. Ассеты 13.8 МБ → 4.7 МБ.

**Остаточный дефект, принят как есть:** у гравела остались открытые
чёрные разрывы у основания ног — так нарисовано в 2008. Замкнутые дыры
(4–50 px на кадр) залить можно, открытые — только кистью. Решено:
оставить.

### Шаг 2 — игра читает PNG

Новый юнит **Sdl2.Image.pas** — биндинги SDL2_image, delayed по паттерну
Audio.pas. Отличие от миксера принципиальное: EnsureImageLib вызывается в
начале RunGame и падает честным сообщением, если DLL нет. Без звука игра
играется, без графики — нет. IMG_Quit в финальном finally: инициализация
без парной уборки — асимметрия, которой в проекте нет нигде.

Четыре точки загрузки SDL_LoadBMP_RW → IMG_Load_RW: Render.Sprites
(кэш спрайтов), Render.Font (атлас), Menu ×2 (LoadTexture /
LoadOpaqueTexture). RW-обвязка не тронута, диффы — по одному имени.

Ссылки .bmp → .png: константы кода (sky, fullmoon, logo, fonty, флаги,
Stars, target*, health, конкатенации в Bullets) и данные (все .mns,
heroes/weapon default.txt, level1/level2.json). Кросс-чек прогнан: каждая
ссылка резолвится в существующий файл.

**tools/TitleCard** тоже поправлен — он линкует Render.Font и без правок
сломался бы: fonty.png в конфиге и сообщении, Sdl2.Image в uses и dproj,
EnsureImageLib перед Application.Initialize.

SDL2_image.dll 2.8.8 win32-x86 в bin\ — PNG-декодер встроен, extra-DLL
не нужны.

**Color key в TSpriteCache оставлен включённым:** на запечённых PNG
чистого чёрного не осталось, вызов молотит воздух. Снос машинерии —
отдельным шагом, кандидат в refactoring.md.

### Версия

2.2.0, не 2.1.2: сменился формат всех ассетов, в поставке новая DLL,
движок больше не читает BMP вообще. Старый bin\ + новый exe = чёрный
экран. Ломающее изменение данных при том же геймплее.


## Сессия: формат наборов спрайтов .mset (2026-08-02, вечер)

Возврат к задаче, отложенной ради PNG. Формат родился в чистом мире:
один тип картинок внутри, никаких «а если BMP».

### Что решено (аргументы в скобках)

- **Один файл на набор.** Манифест внутри, не рядом. Внешний pack.json
  был отвергнут: два файла на один набор — это два источника правды,
  которые однажды разойдутся. Читаемость git-диффов добывается через
  textconv (`SpritePackCli list`), а не вторым файлом.
- **Наборы в репе, россыпь PNG — нет.** Распаковщик возвращает байты
  один в один, значит хранить и то и другое — хранить дважды. Цена:
  каждая правка картинки кладёт в историю новую копию набора; лечится
  не дроблением наборов, а привычкой коммитить пачкой.
- **Владение.** Монстр владеет своими спрайтами (`monsters.json` назовёт
  набор), герой — умолчание движка, уровень объявляет ТОЛЬКО окружение.
  Первый вариант (уровень перечисляет и монстров) отвергнут: два списка,
  которые обязаны совпадать, однажды не совпадут.
- **Тематическое деление вместо поуровневого.** Уровень 2 уже берёт
  тайлы уровня 1 — деление по уровням врёт с первого дня. Итог: 12
  наборов по сюжету изображения.
- **Ключевой довод про размер:** загрузка ленивая, поэтому размер
  набора не стоит машине ничего. Цена только человеческая — найти тайл
  в палитре редактора. Значит режем не ради загрузки, а ради глаз.
- **Именованные последовательности с описанием.** Задел: движок
  спрашивает alive/death, формат принимает любое имя. У самой
  последовательности есть свободное поле description — под скорость,
  зацикленность, кадр удара, когда что-то начнёт это читать.
- **Два exe над одним юнитом**, а не один с AttachConsole: VCL-программа
  с командной строкой не ведёт себя как консольная, и лечится это
  костылями. Логика всё равно в Sprites.Sets, обёртки тонкие.

### Формат

10-байтовая шапка ('MSET', версия word, размер манифеста cardinal),
UTF-8 JSON, затем PNG подряд без разделителей. Границы — из манифеста
(offset+size), смещения считаются от начала блока картинок, чтобы
правка манифеста не двигала ни одного изображения. Разделителей нет
сознательно: их байты могут встретиться внутри PNG.

Спека: docs/MSET-FORMAT.md.

### Инструменты

`SpritePackCli` (pack / list / unpack) и `pack-sets.ps1`. Списки 2008
разбираются по длине: 16 строк → alive+death, 24 → walk+death+henshin,
иначе одна группа frames. Это не эвристика — ровно так делил каждый
загрузчик 2008, длина и была форматом. Использование одноразовое,
миграционное; дальше единственный источник — манифест.

Тайлы нельзя разложить по тематическим папкам, пока игра читает их с
диска по старым путям, поэтому скрипт раскладывает во временную папку,
пакует и убирает. Костыль уедет вместе с россыпью.

### Проверено

Круг pack → list → unpack → сравнение хешей: 16 из 16 файлов гравела
совпали побайтово. Собрано 29 наборов (15 монстров, герой, оружие, 12
тайловых), не разобранных файлов — ноль.

### Находки по ходу

- **level2 берёт из папки level1 ровно один тайл** — `doom1`. Вся
  легендарная «второй лезет в первый» — одна плитка.
- **`textures\d8.png` побитово равен `monsters/gravel/d8.png`** и при
  этом честно используется в палитре второго уровня: кадр взрыва в
  роли тайла.
- **Четыре имени задвоены** (`mash1..3`, `pustota` в корне и в level1\)
  и это РАЗНЫЕ картинки. Разведены по разным наборам; при переходе на
  наборы одно из имён стоит переименовать.
- **Рельсы и вагоны для будущего уровня с рудным поездом уже нарисованы
  в 2008** — 20 плиток в наборе `railway`.
- **`TSpriteCache` дедуплицирует по имени файла**: `e1.png` двух
  монстров грузится один раз. В мире наборов у каждого свой `e1`, общий
  кэш исчезнет и взрывы продублируются в памяти. Некритично (мегабайты),
  но если понадобится — общий набор `shared`. Решать на шаге 3.

### Дальше: загрузка в игре, пятью шагами

1. `TSpriteCache` учится второму источнику; наружу тот же `Get(name)`,
   папочный режим остаётся живым.
2. Один подопытный: гравел из набора, остальные из папок. Плейтест.
3. Остальные монстры и герой. Здесь умирают .mns и default.txt.
4. Окружение: `"spriteSets"` в level*.json. Здесь меняется формат
   уровней.
5. Уборка: папочный режим уходит, россыпь уходит из bin\, наборы въезжают
   в реп. **Это и будет 2.3.0** — снова ломающее изменение данных.

Инструмент сам по себе версию игры не двигает: версия маркирует игру,
а не репозиторий (тот же случай, что TitleCard).


## Сессия: движок читает наборы — шаги 1–3 (2026-08-03)

Пять шагов плана, пройдено три с половиной. Каждый шаг — плейтест,
все зелёные.

### Шаг 1: кэш с двумя источниками

`TSpriteCache.AttachSpriteSet` — кэш переключается с папки на набор.
Набором кэш НЕ владеет (один набор может кормить несколько кэшей;

Ключевой ход миграции: в режиме набора `Get` срезает расширение, так
что `Get('1.png')` и `Get('1')` — один слот. Все старые вызовы работают
против наборов без единой правки — это и позволило переезжать по
одному подопытному.

Перегрузка `LoadAnimSet(cache, spriteSet)`: та же TAnimSet 8+8, кадры
из последовательностей alive/death, длина проверяется строго — TAnimSet

### Шаг 2: пилот-гравел

Шлюз удалён на шаге 3 (удалён, не расширен — как и было записано в

## Сессия: окружение, квалификатор, уборка — шаги 4–5 (2026-08-05)

План из пяти шагов пройден. Игра целиком живёт на наборах, россыпи
картинок в поставке больше нет.

### Шаг 4: окружение

`"spriteSets"` в level*.json — массив имён в порядке разрешения. Кэш
получил СПИСОК подключённых наборов вместо одного: первый содержащий имя
побеждает. При поиске отбрасывается не только расширение, но и путь —
`level1\doom1.png` и `doom1` один спрайт, поэтому написания 2008 в
палитрах работают без правки данных.

Тайловый кэш переехал в `LoadLevel`: с наборами он принадлежит уровню,
как фоновый всегда принадлежал. Фоны экранов идут КОНВЕНЦИЕЙ, а не
объявлением: `<assetsDir>-backdrops.mset`. Объявленный, но отсутствующий
набор — исключение, не фолбэк: фолбэк существует для имён, не для
наборов.

Раскладка тайлов: 12 тематических наборов вместо двух папок. Проверено
машинно — все 191 имя палитр разрешается.

### Квалификатор и проверка неоднозначности

Проблема: `pustota` и `mash1..3` есть в двух наборах РАЗНЫМИ картинками.
Голое имя разрешается порядком объявления — молча. Перестановка наборов
в JSON поменяла бы картинку, не тронув палитру.

Решение из двух частей (квалификатор — идея автора):
- **`набор:имя`** — квалифицированное имя идёт только в названный набор.
  Разделитель ':' выбран потому, что не путается ни с расширением, ни с
  путём. Ключ кэша несёт квалификатор, иначе два `pustota` схлопнулись
  бы в один слот.
- **`AmbiguousNames(палитра)`** — движок отказывается грузить уровень,
  который просит ГОЛОЕ имя, живущее в нескольких объявленных наборах, и
  перечисляет виновных.

Важная поправка по ходу: первая версия проверяла НАБОРЫ (два набора с
одним именем = ошибка) и ругалась даже на уже квалифицированную палитру.
Правильный критерий — что уровень ПРОСИТ, а не что наборы содержат.

Прецедент не выдумывали: проверка сразу нашла реальный случай, второй
уровень получил `common:pustota`. Один на 191 имя.

Договорённость на будущее: редактор уровней будет ЧИТАТЬ и голые, и
квалифицированные имена, а ПИСАТЬ всегда квалифицированные. Инструмент
строже формата — здоровая асимметрия; заодно открыть-и-сохранить
нормализует палитру первого уровня без единого клика.

### Меню, шрифт, звёзды

`ui.mset`: небо, луна, логотип, флаги, 10 звёзд, 3 атласа шрифта.
Собраны в один набор по назначению, а не по папке (звёзды лежали
отдельно). Меню получает наборы ИНЪЕКЦИЕЙ, а не ищет файлы само:
композиционный корень решает, что существует.

## Сессия: курсор, съёмочный конфиг, разбор окна (2026-08-09)

Вечер ушёл на трейлер, но вынес две правки в код и одну поправку к
записанному раньше диагнозу.

### Системный курсор

Находка: `SDL_ShowCursor` не вызывался НИКОГДА — ни биндинга, ни вызова.
Игра всё время рисовала свой прицел (`Hero.FCrossDX/DY = 9/10`,
`Menu.DrawCursor` с четырьмя кадрами) поверх живой стрелки Windows.

На экране не замечалось: две картинки едут вместе, глаз читает одну.
Вылезло на записи экрана — там композиция честная, и стрелка сидит
рядом с прицелом, а не в нём.

Правка: `SdlCursorDisable/Enable` + `SDL_ShowCursor` в `Sdl2.Core`,
один вызов в `CreateWindowAndRenderer` после проверки рендерера.

Гасится БЕЗУСЛОВНО, без гейта на фуллскрин. Правило: рисуешь свой
курсор — прячешь системный, режим окна ни при чём. SDL прячет стрелку
только над своим окном, поэтому оконная отладка ничего не теряет.
`SDL_SetWindowGrab` намеренно НЕ трогаем: разработчик должен иметь
возможность увести мышь из окна.

TitleCard создаёт своё окно и правки не касается — там курсор нужен.

### Съёмочный конфиг: tickRate 30

Записанный геймплей дёргался при том, что на экране был гладким.
Причина не в захвате, а в цепочке частот: логика 33 Гц → OBS 60 →
таймлайн 30. 33 в 30 не делится, примерно каждый десятый шаг логики
не попадает ни в один кадр монтажа.

Съёмочный `config.json`: `tickRate: 30`. Тогда 30 → 60 → 30, целое на
каждом стыке. Игра идёт на 9% медленнее канона (`CountdownTicksPerDigit`
считает в 33-х) — в трейлере невидимо.

Продакшн-значение остаётся 33 и остаётся каноническим. Это костыль
съёмки, не решение; настоящее решение — интерполяция рендера (пункт 19),
после неё тик вернётся к 33 навсегда.

### Поправка: причины дёрганья в окне

Ранее в записке значилось: окно тормозит из-за DWM-композитора на
многомониторной конфигурации с разными частотами. Живой разбор показал,
что на референсной машине главная причина была другой и внешней —
**основная панель работала через Microsoft Basic Display Driver.**

Как получилось: iGPU был отключён в диспетчере устройств (попытка
отдать все выходы дискретке), встроенная панель разведена на Intel и
осталась без драйвера. Частота обновления «Неизвестно», ускорения нет,
композитору не под что синхронизироваться. Отсюда ровное метрономное
дёрганье в окне при полностью гладком фуллскрине.

Включение iGPU обратно вернуло панели 165 Гц и сделало окно маслом БЕЗ
единой правки в движке.

Что из старого диагноза остаётся верным: фуллскрин идёт независимым
flip-ом мимо композитора, окно — через DWM; асимметрия структурная.
Что оказалось неверным: списывать всё дёрганье окна на неё.

Отдельно: ступенчатость 33 Гц без интерполяции — пол гладкости,
ниже которого не опуститься никакой настройкой среды. Проверено тестом
`tickRate: 120` (фуллскрин — масло, окно — тот же метроном, только реже).
Это подтверждает приоритет пункта 19, но лечит другую болезнь, чем DWM.

**Вывод для будущего: не подгонять архитектуру движка под особенности
одной рабочей станции.** Хинт D3D11 был общей проблемой и остаётся.
Костыли под трёхмониторный DWM — нет.

## Сессия: тряска экрана (2026-09-26)

Задача: дёшево добавить динамики. Взрыв бочки - экран слегка вздрагивает,
цепочка бочек - сильнее, но с потолком; ярость и смерть босса - на всю;
хеншин - волны как бочка, финал сильнее. Всё это должно складываться в
один процесс: бочки рвутся одна за другой, очередь трясок не нужна.
Ориентиры: "The Art of Screenshake" (Nijman, Vlambeer, 2013) - свежий
случайный сдвиг каждый кадр, без сглаживания; "Juicing Your Cameras With
Math" (Eiserloh, GDC 2016) - модель травмы.

### Модель: один метр травмы

Render.Shake, TScreenShake. Одно число T в [0, 1):
- взрыв доливает: `T := T + A * (1 - T)`. Не clamp: каждый следующий
  заполняет долю ОСТАВШЕГОСЯ, цепочка бочек ползёт к потолку и не
  упирается в него стеной (0.4 -> 0.64 -> 0.78 -> 0.87...);
- остывание линейное, 0.03 за тик - около секунды на полный метр;
- амплитуда = T² x 8 юнитов. Квадрат и есть "чуть-чуть от одной,
  заметно от трёх": бочка ~1 юнит, три подряд ~5, босс 8 (16 px окна).
- сдвиг - свежий бросок в [-A, A] на каждый тик, целые юниты. Шум типа
  Perlin превратил бы тряску в качку.

Каналы: мир (тайлы, пули) едет одним куском; герой и монстры едут вместе
с миром плюс своя добавка 25% от амплитуды. Больше - герой заметно
отлипает от платформы под ногами. Меньше - фигуры приклеены к земле, и
тряска читается как дрожь картинки, а не мира.

### Три решения

1. Фон стоит, тайлы едут. Задник - дальний план, параллакс на халяву;
   то, что тряска открывает у края, - небо, а не пустота. Шаттл на
   первом экране level1 отклеился бы от стены, но там нечему взрываться.
   Для этого DrawScreen в Render.Tiles разрезан на DrawBackground и
   DrawTiles, обе наружу; сам DrawScreen без вызовов и удалён.
2. Сдвиг считается раз в логический тик (Tick в Update), не в кадре.
   Хрусткая 33-герцовая тряска в духе 2008; кадровая гладкость упирается
   в пункт 19 (интерполяция), и тряска не должна идти впереди него.
3. Свой xorshift вместо Random. Глобальный Random кормит PickSpawn
   босса; тряска, дёргающая его на каждом тике, меняла бы, что падает с
   неба. Сид константа, поток не сидируется - воспроизводимость не
   нужна, нужна только независимость.

Механика: TSpriteRenderer.Origin - сдвиг, который получают ВСЕ Draw* -
включая DrawRect, потому что пули рисуются им. Слои, которым стоять
(задник, курсор, HUD), рисуются с Origin = NoShake. Render в dpr
выставляет Origin перед каждым слоем и обнуляет в конце - порядок
слоёв там и есть спецификация, кто трясётся.

### Дозы (константы в dpr, рядом с расписанием хеншина)

| Событие | Травма | Хук |
|---|---|---|
| Бочка, танк, mount, платформа (explodesOnDeath) | 0.4 | DrainMonsterEvents, meDied |
| Волна хеншина (каждая из пяти) | 0.4 | TickHenshin |
| Финал хеншина (веер FinishFan) | 0.7 | FinishHenshin |
| Ярость босса (RageWave) | 1.0 | DrainMonsterEvents, meBossRage |
| Смерть босса (двойной веер) | 1.0 | DrainMonsterEvents, meDied + EndsLevelOnDeath |
| Бонус "Взрыв" | 0.7 | ActivateQueuedBonus |
| Бонус "Огненный дождь" | 0.5 | ActivateQueuedBonus |

Аура и здоровье не трясут - в них нечему бахать. Ранение героя не
трясёт: Vlambeer трясёт и от удара по игроку, но в задаче не было -

в dpr, через события, которые и так дренируются каждый тик.

Цепная реакция бочек ловится тем же meDied: каждая бочка умирает через

## Сессия: HUD примитивами и режим 2008, v2.5.0-2.5.2 (2026-09-26)

Задача: кругали heroes\health.bmp в углу выглядели на 2008-й, и не в
хорошем смысле. Условие: никаких спрайтов, всё рисуется графикой.
Пять вариантов в живом HTML-демо (сегменты, кардиомонитор, кристаллы на
SDL_RenderGeometry, бак скафандра, точки над героем) - выбран
кардиомонитор в углу, точки над героем и монстрами отложены на
следующую итерацию. Потом симметричная панель очков справа. Посреди
всего родился режим 2008 - "хорошая мысля приходит опосля".

### Решения (аргументы в скобках)
- Норма здоровья 5 на всех сложностях, потолок 10. Первые пять ячеек -
  "здоров", пустые остаются контурами (сложность видна сразу: hard
  стартует 4/5, wild 2/5). Всё выше - бонус от аптечек, салатовыми
  ячейками за засечкой; урон съедает их первыми. Из трёх способов
  показать бонус (за чертой / второй слой / щит) - "за чертой": считать
  ячейки быстрее, чем ядра, а щит врёт про механику.
- Бонус салатовый, не жёлтый (жёлтый занят сигналом "2 жизни"; прицел
  уже говорит зелёный/жёлтый/красный - HUD на том же языке).
- Очки - не очки, а заряд бонуса: число + шкала до 50 с рисками по 10,
  на 50 награда выпадает, шкала салатовая с её значком, число растёт
  дальше (60, 100, до 999 на экране), пока награду не потратил. Для
  этого оплата переехала на активацию (отступление 12). Ряд серии из 10
  ячеек внизу панели - механика была, игрок её не видел.
- Режим 2008: только уровни 1-2 (флаг в данных уровня, не `if Level <=
  2`), выключен по умолчанию, живое переключение из меню, в коде enum
  `TEra = (eraRemake, era2008)` - Boolean через полгода превратился бы в
  "true это который?". Название: `2008 mode` / `Режим 2008` - игрок не
  знает слова legacy, а год знает. Меню: пункт под сложностью, перед
  Credits, клик переключает на месте (двум состояниям подменю не нужно).
- Один выбор в точке сборки, а не `if Era` по коду: абстракции
  THealthHud / TScoreHud, класс выбирает ApplyLevelEra. Первые "две
  реализации одного" в проекте - держать список переключаемого коротким.
- HUD наблюдает, а не слушает: Tick(health, ...) раз в тик, разницу с
  прошлым значением ловит сам - в HurtHero/CureHero/RestartLevel ни
  одного хука. Побочный эффект: старт уровня 0 -> 5 выглядит как аптечка
  ("прибор включили"), смерть с бонусом в руках - как трата. Принято.

### Как устроено
- Hud.Draw - одна кисть на обе панели: SDL_RenderFillRectF с альфой,
  аддитивный Glow (SdlBlendModeAdd = 2, одна новая константа в
  Sdl2.Core, ноль новых импортов), рамка из четырёх прямоугольников,
  цифры 3×5. Панели 118×32 по углам, ряд ячеек 7×4 внизу обеих.
- Кардиомонитор: кольцевой буфер 88 сэмплов по два за тик, форма PQRST,
  темп 62/70/92/118/152 уд/мин по здоровью, прямая при нуле, шум 10 тиков
  после удара. Свежее ярче, тёмный разрыв в 4 сэмпла ПЕРЕД бегунком
  (в демо было наоборот - в Delphi сделано как на настоящем мониторе).
  Шум - свой xorshift (TXorShift в Hud.Draw): Random кормит таблицу
  спавна босса, та же ловушка, что у тряски.

## Сессия: ряды здоровья над героем и монстрами, v2.5.3 (2026-09-27)

## Сессия: раскол кадра и экрана, v3.0.1 (2026-09-27)

Задача: одна константа GameWidth (в Hero.pas!) значила и "ширина кадра",

Широкий экран разводит эти два смысла (кадр 16:9, уровень 4:3 по центру),

### Решения (аргументы в скобках)
- Новый юнит Game.Space, по образцу Game.Bonus: словарь, а не механизм.
  ЭКРАН - ScreenCols/ScreenRows/ScreenWidth/ScreenHeight (16x12, через
  TileSize, чтобы 512 = 16 * 32 проверял сам себя). КАДР - FrameWidth/
  FrameHeight, сегодня = экрану. Хозяин размеров - не герой: GameWidth в
  Hero.pas был исторической случайностью.
- Правило выбора записано в шапке юнита: клетка, стена, дверь, пуля за
  краем - Screen; панель в углу, текст по центру, логический размер
  рендерера, меню - Frame. Никогда не "тот, что рядом", даже пока числа
  равны.
- Оракулы клеток остались в форме 2008 (Trunc(16 * X / 512 + 1)), только
  через константы: ScreenCols * X / ScreenWidth. Форму не упрощал до
  X / TileSize: результат тот же, но цитата теряется, а выигрыша нет.
- Menu: ScreenWidthUnits/ScreenHeightUnits ушли, вместо них FrameWidth/
  FrameHeight; UnitsPerNdcX/Y остались только для РАЗМЕРОВ квадов 2008
  (луна, лого, звёзды). Центр луны - FrameWidth / 2, а не UnitsPerNdcX:
  в широком кадре луна должна висеть по центру кадра, а не окна 2008.
- Литералы, выведенные из 512/384, стали выражениями с комментарием-числом:
  PatrolRightLimit = ScreenWidth - SpriteSize (480), BelowFloorY =
  ScreenHeight - 17 (367), огненный дождь - ScreenWidth div GridStep
  колонок (32) на ScreenHeight div GridStep рядов (24), правый край
  экрана "<> 16" - "<> ScreenCols". Число рядом, чтобы диф с 2008 читался.
- Параметры HUD переименованы по смыслу: THudCharge и TMessageBoard берут
  AFrameWidth (панель в углу и заголовок по центру - это кадр).
- Render.Font 256/192 не тронуты: это метрики глифов из NDC-математики
  2008, размеры, а не положения. Render.Tiles уже считал экран из
  GridWidth уровня - там всё было правильно с самого начала.

## Сессия: шрифт fonty в HD, v3.0.4 (2026-09-29)

Атлас fonty перерисован DALL-E по образцу 2008 (как до этого логотип) и
вычищен скриптом против оригинала. В ui.mset: `fonty` - новый, 1024x1024,
клетка 64; `fonty-2008` - старый, байт в байт. Вернуть вид 2008 - одна
константа FontFileName в dpr.

### Сверка с 2008 (по клеткам, скриптом)
- Раскладка цела: все 256 клеток на месте, ни одна не опустела и не
  появилась. Сдвиг рамки чернил - медиана 0.8 px, максимум 1.75 px в
  пикселях 2008 (':' и ';'). Толщина штриха в среднем +5%.
- Квадраты-заглушки ('"', '=', '‡', '€', 'Ў', 'Є', ...), '&' в виде '_',
  'µ' в виде 'В', черта над строчной 'o' - всё это было в атласе 2008 и
  сохранено как есть. Из текстов игры (lang, level, monsters) на
  заглушку попадает только '=' в полях note, которые не рисуются.
- DALL-E оставил около 1000 px чужих чернил у границ клеток (кусок
  заглушки '=' под '-' и т.п.). Правило чистки: фрагмент выживает в
  клетке, только если глиф 2008 этой клетки имеет чернила там же.
- Цвет чернил у DALL-E уехал в (204,246,0); перекрашено в (188,255,0)
  2008 с сохранением яркости - иначе ячейки сложности в меню
  (MenuInkColor) разошлись бы с подписью.
- Внутри каждой клетки - пустая рамка 2 px: линейный фильтр читает
  полтекселя за Src, соседняя заглушка иначе просвечивала бы полосой.

### Решения (аргументы в скобках)
- Клетка 64, не 80 и не 56 (симуляция выборки на 1080p: мелкий текст
  уменьшается из 64 в ~2.4 раза - билинейный ещё держит; отсчёт хеншина
  до 132 юнитов растёт до ~370 px - 56 уже мылит; 1024 - степень двойки).
- Render.Font берёт клетку из размера картинки (FAtlasCellPx), атлас
  обязан быть квадратом со стороной кратной 16 - иначе EFontError с
  размерами. FontCellPx = 28 остаётся мерой дизайна 2008: Menu и
  TitleCard делят на него пиксели, замеренные на старом атласе, и эти
  доли верны для любого размера.
- Фильтр - nearest по умолчанию (FontFiltering в dpr). Живой прогон
  трёх режимов: линейный не дал заметной чёткости, зато съел твёрдый
  ступенчатый край - а по нему шрифт 2008 и узнаётся. Опасение, что
  nearest потеряет штрихи при уменьшении из 64, в игре не подтвердилось.
- Атлас в двух текстурах, nearest и linear; TMoonFont.Filtering выбирает
  по размеру текста: linear / nearest / linear мелкий + nearest крупный.
  Не одна текстура с переключением фильтра: пакетный рендер читает
  фильтр в момент сброса, и весь кадр ушёл бы в последний режим.
  Клавиша N (DEBUGKEYS) листает режимы, имя - в заголовке окна. Атлас
  2008 - nearest в любом режиме, линейной копии у него нет.
- TitleCard свой TMoonFont не настраивает и рисует линейно.

### Открытое
- Живой прогон: HUD-тикер в движении (мерцание при уменьшении), бегущая
  строка (ушла в 3.0.8 - вместо неё терминал), отсчёт 3-2-1, меню с
  флагами, TitleCard.
- Широкие Ъ Ы Ю касаются краёв клетки, а крупный текст идёт с
  нахлёстом 20% - проверить глазами, не режется ли край.

Коммиты серии: Read the font cell size from the atlas image; Redraw the

filtering be cycled live (N); Draw the redrawn font nearest by default;

## Сессия: настройки игрока в settings.json, v3.0.9 (2026-09-29)

config.json - дефолты поставки, игра его только читает. Выбор игрока
пишется в %APPDATA%\Moon2D\settings.json и перекрывает config.json по
ключам. Полный экран теперь запоминается. Delphi у Клода нет - серия
написана без компиляции, первая сборка и прогон за Ильёй.

### Решения (аргументы в скобках)
- settings.json в %APPDATA%, а не рядом с exe (вне папки игры он физически
  не попадает ни в git, ни в bin\, ни в архив - охрана не нужна; переживает
  распаковку новой версии поверх старой; прав не требует, а запись рядом с
  exe в Program Files молча падала бы). Путь - TPath.GetHomePath, на
  Windows это CSIDL_APPDATA (Roaming).
- Слои: Defaults <- config.json <- settings.json, каждый файл перекрывает
  только свои ключи. Битый слой отбрасывается целиком, нижние остаются
  (раньше любая ошибка давала Defaults на весь конфиг). В settings.json
  лежат только тронутые игроком ключи, остальное берётся из config.json;
  туда же руками кладётся личная кухня (vsync, fpsCap, размер окна).
- Отсутствующий ключ держит значение нижнего слоя: difficulty и language
  читаются с дефолтом "текущее значение", а не '' (иначе settings.json без
  difficulty сбрасывал бы сложность в normal).
- SaveGameKey -> SaveKey(файл, секция, ключ, TJSONValue): секция стала
  параметром (fullscreen живёт в window), значение типизировано; SaveKey
  владеет значением на всех путях, ранние выходы включая. Папка создаётся
  при первом сохранении. Неразбираемый файл по-прежнему не перезаписывается.
- Полный экран запоминается (SaveWindowFullscreen). Развилка:
  ToggleFullscreen - выбор игрока (Alt+Enter, пункт меню), пишет;
  SetFullscreen - механика без записи. Финальный экран перед браузером зовёт
  SetFullscreen(False): игрок окно не выбирал, следующий запуск не должен
  его помнить.
- vsync в поставке true - релизная конфигурация из разбора статтера на
  D3D11 (пункт 11). false в config.json стоял с первого коммита 2.0: личная
  кухня, уехавшая в поставку; её место теперь в своём settings.json.
- TMoonGame.Create принимает TGameConfig целиком (было шесть параметров,
  два из конфига).
- Сборщик (make-release.ps1 v5, вне репо): версия по умолчанию читается из
  Game\Game.Version.pas; подмена config.json через git show убрана - игра
  его не пишет, а bin\ снова целиком whitelist; вместо неё предупреждение,
  если в bin\ есть незакоммиченные изменения (ловит и правленые
  level*.json/monsters.json); README.txt: SETTINGS под два файла, ключ era
  ушёл, при чёрном экране первым советом Alt+Enter.

### Проверить живым прогоном
- Чистый профиль (нет %APPDATA%\Moon2D): игра стартует из config.json;
  клик по сложности создаёт папку и файл с одной секцией game.
- Alt+Enter -> перезапуск -> окно запомнено; и обратно.
- Из полного экрана клик по ссылке на финальном экране -> перезапуск ->
  снова полный экран.
- Руками сломанный settings.json -> игра стартует с config.json, клик по

- После игры git status по bin\ чистый.

### Открытое
- Относительные пути к данным (sprites\, lang\, level*.json, config.json)

## Сессия: события уровня из JSON, v3.0.10 (2026-09-29)

Первые события в игре. Повод: подсказка медлаба (экран 12) печаталась
посреди боя с танками, а hintHoldWhileAlive только морозил ей таймер.
Нужно было другое - не показывать, пока охрана жива, - и это уже условие,
а не удержание. Заодно задел на уровни 3+: взрыв, спавн, любая сцена по
триггеру.

### Решения (аргументы в скобках)
- Событие = экран + условие + задержка + список действий, три независимых
  слоя (условие не знает о действиях, задержка - общий модификатор, а не
  свойство allDead: "вошёл на экран, через две секунды музыка" пишется
  сразу). Отдельная секция events в JSON, старые triggers на сущностях не
  тронуты - миграция потом или никогда.
- Кого ждём - метки на расстановках (`"tag": "labGuard"`), не тип
  монстра: из шести тел экрана 12 вниз к герою приходят четыре (два
  танка, бетонер над дырой x=12, самка грейвела - она без проверки края
  и спрыгивает; самец x=15 и два бетонера остаются наверху). По типу это
  не выразить, по метке - решает автор уровня.
- Условия опрашиваются каждый тик (как HintHeld раньше), а не приходят
  событиями meDied: труп остаётся трупом, опрос не теряет ничего, и
  условие - это предикат над состоянием, а не бухгалтерия подписок.
- Задержка идёт, пока условие держится; сбой условия начинает отсчёт
  заново. Над трупом героя директор не тикает: рестарт всё равно взводит
  экран заново (ReArm рядом с перевзводом триггеров).
- Модель и парсер - в Core (`Levels.Events`, редактор будет их писать),
  исполнитель - в `Game/Events/` (место было обещано при раскладке).
  Директор получает доску сообщений и колбэк музыки - как хеншин получает
  сцену и CureHero; поле монстров приходит с каждым тиком, потому что
  рестарт рождает его заново.
- Музыка: `ChangeMusic` в dpr - один метод для триггеров и событий
  (играет и запоминает трек для рестарта), вместо второй копии трёх строк.
  `TickerNoticeTicks` переехал в Hud.Messages к BigMessageTicks - директору
  нужна длительность, до dpr ему не дотянуться.
- Опечатки умирают на загрузке: неизвестное условие или действие,
  событие без id или без действий, allDead без тега, экран вне списка,
  тег, которого не носит ни одна расстановка (такое сработало бы сразу -
  держать некому).
- hintHoldWhileAlive снесён вторым коммитом (единственный пользователь -
  медлаб; вместе с THintHold, HintHeld, HoldTerminal, Held терминала,
  AnyAliveOnScreenOf). Удержание как механизм не бесполезно, но без
  клиента - код в стол.
- Расширение проверяется ценой следующего события, а не лишним кодом
  сейчас: условие - член перечисления + слово в EventConditionIds +
  ветка ConditionHolds; действие - то же с EventActionIds и Play.
  Пока условий два, ConditionHolds - if; с третьим станет case.

### Грабли сессии
- В `{ }`-шапке юнита нельзя приводить JSON: первая же `}` закрывает
  комментарий, дальше компилятор читает JSON как Паскаль (50 ошибок из
  одной). Пример JSON - в `//`-комментарии над записью.
- `Game\Events\` на два уровня ниже корня: `{$I ..\..\Moon2D.inc}`.

### Открытое
- Кандидаты в следующие условия/действия, когда появится клиент: heroAt
  (область экрана), afterEvent (цепочки), spawn, explode (веер + звук +
  тряска), swapSprite. Не раньше уровня, которому это нужно.

### Коммиты
Add level events from level JSON (3.0.10); Remove the hint hold; the
events replace it; Update the docs for level events. Тег 3.0.10 - на

## Сессия: план релиза 3.0 - объекты и эффекты (2026-09-30, план, кода нет)

Повод: заставка и меню стали чёткими и живыми, игровой мир рядом с ними -
мыло 2008 года. Полная перерисовка арта отложена (фаза 3, после
редактора), но дешёвый и серьёзный апгрейд играбельности есть: HD-задники,
статические объекты, живые эффекты. Состав и граница релиза - в стратегии
("РЕЛИЗ 3.0 - ГРАНИЦА И СОСТАВ"), здесь - решения по коду и данным, чтобы
в следующем чате "делаем" значило одно и то же.

### Решения (аргументы в скобках)
- Объекты - дополнение к тайлам, не замена: уровень может стоять целиком
  на объектах, целиком на тайлах или на обоих, одно другого не отменяет
  (уровни 1-2 живут на тайлах; объекты - это ровно то направление,
  которое выбрано для текстур будущих уровней: сетка коллизий + объекты
  сверху, так что слой объектов - первая половина будущей модели уровня,
  и редактор получит её готовой).
- Объект = спрайт произвольной формы в произвольной точке экрана, без
  коллизий (коллизии остаются за сеткой; корабль вместо шаттла - вид, по
  нему бегают по тайлам под ним, как сейчас по шаттлу в заднике).
- Динамические эффекты НЕ привязаны к статическим объектам (маячок
  ставится куда угодно теми же координатами; дым - просто текстура в
  точке; прицеплять к объекту нечего - объекты не двигаются до вагонов
  уровня 4).
- Каждый переиспользуемый динамический объект - свой юнит со своими
  свойствами (у маячка и дыма разные "боссы": маячок переписывают, когда
  захотелось строб, дым - когда захотелось ветер).
- Родитель по образцу VCL, но только система координат: Parent = nil -
  прибит к экрану гвоздями, Parent = монстр (по тегу) или герой - едет за
  ним. Владения и времени жизни родитель НЕ несёт (дым босса должен
  висеть над воронкой после взрыва, а не умирать с боссом в тот же кадр).
- Ссылку на монстра не хранить: якорь держит тег и каждый тик спрашивает
  поле, где монстр; "нет такого" - эффект остаётся на последней позиции
  и дотлевает (ни висячих указателей, ни `if Assigned`; поле монстров
  рождается заново на рестарте - как у директора событий).
- Эффекты - абстрактный класс TLevelEffect, не интерфейс (эффекты лежат в
  TObjectList, он владелец; интерфейс тащит refcount - два хозяина у
  одного объекта; тот же приём, что THealthHud/TScoreHud/TGameApp: игра
  держит базовый тип и не спрашивает, кто внутри; вид известен только на
  границе JSON, где строка kind становится вызовом конструктора).
- TMonster интерфейса не получает (TObjectList + refcount = монстр
  освобождён, список держит труп; классика, не лечится - обходится тегом).
- Вспышки героя - не объекты и не юниты, а пресеты эмиттера (залп, потом
  тление); живут там, где их зовут: Game.Henshin и кластер возрождения в
  dpr (модуль под пресет - класс в плаще).
- Эмиттер - один на всех: искры логотипа, дым и маячки уровня, эффекты
  героя (один механизм, четыре клиента; синий костёр льда рифмуется с
  костром на логотипе - меню и игра начинают говорить на одном языке).
- Задники уровня 1 в HD и без вклеенных корабля/спутника (генерируются
  за минуты, суть не меняется; под 16:9 позже переделываются так же).

### Эмиттер (шаг 1, рефакторинг без бампа)
Menu.Embers - не общий эмиттер: сиды берутся из контура букв (альфа
текстуры, нормали к воздуху). Общее в нём - жизнь частицы: рождение,
полёт со сносом (lift), остывание цвета, затухание, перерождение. Это и
выделяется в Core/Effects.Emitter; источник рождения - параметр:
- контур (сиды с нормалями - остаётся в Menu.Embers как поставщик сидов);
- точка (дым, маячок-искры, вспышки);
- отрезок (след героя: точки между позицией прошлого и этого тика).
Параметры частицы: стартовая скорость и разброс, снос, время жизни,
размер, цвет от -> до, blend. Два способа рисовать: точечное свечение
через Render.Glow (искры, маячки - аддитивно) и спрайт (клуб дыма -
обычная альфа). Проверка шага: костёр над логотипом не изменился.

### Объекты уровня (шаг 2)
- Core/Levels.Objects - модель и парсер (редактор будет писать):
  ```
  "objects": [
    {"sprite": "level1-objects:ship", "screen": 1, "x": 0, "y": 224,
     "layer": "behindTiles", "tag": "ship"}
  ]
  ```
  x/y - юниты экрана (не кадра: широкий кадр их не тронет, Game.Space
  для того и разведён); layer - behindTiles / aboveTiles; tag -
  необязательный, тот же словарь, что у расстановок и событий.
- Core/Render.Objects - рисует объекты экрана для слоя (по образцу
  Render.Tiles: DrawBackground / DrawTiles, отдельные вызовы, чтобы
  слои трясти по-разному). Свой TSpriteCache с DisableColorKey и честные
  PNG с альфой (иллюминаторы корабля и тень спутника - чёрные, через
  color key они бы пропали; на светлом задке незаметно, на первом тёмном
  - сразу). Набор по конвенции `<assetsDir>-objects.mset`, как
  `-backdrops`, в spriteSets не объявляется.
- Порядок слоёв в TMoonGame.Render: задник (NoShake) - объекты за
  тайлами (scWorld) - тайлы - объекты перед тайлами - пули - монстры -
  герой - эффекты (канал якоря) - курсор и HUD (NoShake).
- Плотность пикселей: корабль рисовать в плотности задника, не тайлов
  (он по сути кусок задника, который научился двигаться; три плотности в
  кадре уже есть - HD-задник, 64 px тайлы, 32 px спрайты, - четвёртая
  лишняя).
- Спутник вынимается из задника - задник последних экранов перерисовать
  без него, иначе два спутника.

### Эффекты уровня (шаг 3)
- Раскладка юнитов, по одному на эффект, целиком в Core (не модель в Core
  + рантайм в Game, как у событий: события рисовать не надо, эффекты -
  надо, и редактору тоже - превью уровня с мёртвыми маячками не превью;
  рисование и так на Render.*, а это Core):
  - Core/Effects.Defs - TEffectPlacement (screen, x, y, tag, parent - один
    раз, а не копией в каждом def: иначе четыре записи с полями
    Screen/X/Y, prefix test размазанный по файлам), TEffectKind + ids,
    TLevelEffect (Tick / Draw(renderer, alpha) / Finished - для залпов;
    маячок не кончается никогда);
  - Core/Effects.Anchor - TEffectAnchor с TryFollow(out point): Boolean
    и TScreenAnchor; якоря к монстру и герою - в Game (им нужны
    TMonsterField и THero);
  - Core/Effects.Beacon - TBeaconDef + парсер + TBeacon;
  - Core/Effects.Smoke - TSmokeDef + парсер + TSmoke;
  - Game/Effects/Effects.Field - владелец TObjectList<TLevelEffect>,
    диспетчер kind -> конструктор, TMonsterAnchor/THeroAnchor, тик и
    отрисовка по слоям, перевзвод на рестарте (рядом с ReArm директора).
- JSON:
  ```
  "effects": [
    {"kind": "beacon", "screen": 1, "x": 96, "y": 208,
     "color": "#ff2020", "brightness": 0.8, "hz": 1.0, "pattern": "strobe"},
    {"kind": "smoke", "screen": 15, "x": 300, "y": 96,
     "sprite": "fx:puff", "rate": 4, "drift": -0.4, "life": 60},
    {"kind": "smoke", "id": "bossSmoke", "parent": "boss", "x": 0, "y": -12,
     "sleeping": true, ...}
  ]
  ```
  parent - тег расстановки или слово hero; при parent x/y - смещение от
  родителя. Строка kind декодируется в enum один раз на границе, дальше
  `case`. Новый эффект = новый юнит + ветка в case. Опечатки умирают на
  загрузке, как у событий (неизвестный kind, экран вне списка, parent,
  которого не носит ни одна расстановка).
- Маячок (Beacon, заградительный огонь): цвет, яркость, частота, характер
  - pulse (синус), strobe (короткая вспышка, долгая пауза - авиационный),
  faulty (дрожь на TXorShift; `Random` не трогать - он кормит таблицу
  спавна босса). Рисуется DrawGlow: цвет - tint, яркость * f(t) - level;
  блик - gsFlare на пике вспышки. Render.Glow это уже умеет, нового
  почти нет.
- Дым (Smoke): спрайт клуба (PNG с альфой; чёрный в клубе - сажа, не
  прозрачность), частота рождения, дрейф вверх, время жизни, лёгкая качка
  вбок, затухание альфы - всё параметры эмиттера с источником "точка",
  blend обычный. Не аддитивный (иначе дым светится, как радиоактивный:
  на Луне канон, но не везде).
- Тряска: эффект с родителем-монстром едет по каналу scMonsters, с
  героем - scHero, прибитый к экрану - scWorld (иначе дым босса дрожит
  не в такт с боссом).
- Действие события startEffect (id): будит эффект с "sleeping": true.
  Клиент - дым босса первого уровня перед смертью: условие - порог
  здоровья босса (ProcessBossThresholds уже знает момент; нужно новое
  условие события или прямой вызов из порога - решить на месте). Два
  механизма, построенные порознь (события 3.0.10 и эффекты), впервые
  встречаются.

### Эффекты героя (шаг 4, пресеты эмиттера)

## Сессия: Селена, текстура глобуса (2026-09-30, код игры не тронут)

Задача: нарисовать Селену для меню - живую Луну из лора, узнаваемую как
Луна, но похожую на снимок Земли с орбиты, а не на атлас. Итог -
инструмент tools/Selene и утверждённая карта в tools/Selene/out; в игру
пока ничего не подключено. План подключения - в стратегии ("ИДЕЯ 3.x -
СЕЛЕНА В МЕНЮ").

### Находки
- moonmap в ui.mset - не честная карта Луны: левая и правая половины
  почти одна картинка (корреляция 0.97 при сдвиге ровно на 1024 px).
  Глобус показывает видимую сторону дважды, обратной стороны у него нет.
  Шва на 180 меридиане нет (разница по краю 7.96 против 7.86 у соседних
  столбцов). Строки у полюсов размазаны прямоугольными полосами - на
  глобусе их закрывает сжатие к полюсу, у Селены там ледяные шапки, а
  рельеф выше 58-68 градусов гасится.
- Настоящие исходники - CGI Moon Kit NASA (svs.gsfc.nasa.gov/4720):
  цвет LROC (lroc_color_poles_2k/4k/8k) и высоты LOLA (ldem_4 1440x720,
  ldem_16 5760x2880, ldem_64), одна проекция с центром на нулевой
  долготе. В титрах - "NASA's Scientific Visualization Studio". Из
  песочницы Claude NASA и S3 закрыты (сеть по белому списку, GitHub
  открыт) - файлы приносить вручную.
- Бассейн Южный полюс - Эйткен на обратной стороне - самая глубокая и
  большая низина Луны; с картой высот он сам становится океаном Селены:
  видимая сторона в морях, обратная - материк и один океан.

### Как рисуется (аргументы в скобках)
- Море = тёмное альбедо (моря Луны - низины из застывшей лавы; лицо
  Луны остаётся узнаваемым). Сначала вычитается засветка фото масштаба
  континентов (иначе затапливается весь более тёмный север), морем
  становятся самые тёмные 28% освещённых строк.
- Высота = яркость над уровнем моря - заглушка до карты высот.
- Цвет суши от климата, не от пятен шума: влажный экватор, пустыни около
  25 градусов, влажные штормовые пояса около 52, у побережья влажнее, с
  высотой холоднее. Тона приглушённые - как на снимках Земли (первая
  версия была яркой и с бирюзовыми ореолами вокруг морей - читалась как
  атлас).
- Рельеф запечён светотенью: высота суши, валы лунных кратеров, горные
  хребты на высокой суше (на фото горы видны тенью, не цветом).
- Реки текут по склону размытого альбедо, виляют, сливаются при встрече
  и видны как лесные коридоры; открытая вода только в устьях длинных
  (синие линии рек с орбиты не видны и выдают карту).
- Облака отдельным слоем: шум с двойным искривлением, вытянут по
  долготе, гуще над экватором и штормовыми поясами (запечённые облака
  не крутятся отдельно и не убираются для ролика).
- Шум считается на сфере, фильтры замкнуты по долготе - нет шва и нет
  стяжки у полюсов. Три шага не замкнуты (уклон, расстояние до берега,
  фильтр мелких озёр) - у шва разница 2.7 против 2.1, глазом не видно;
  замкнуть при следующей правке художника.
- Всё под сидом: тот же moonmap даёт ту же планету бит в бит (сверено -
  инструмент в репозитории воспроизводит утверждённые файлы точно).

## Сессия: HD-задники уровней 1-2, v3.0.11 (2026-09-30)

Первый шаг релиза 3.0 со стороны арта. Задники 2008 - 512x512 (степень
двойки ради текстур OpenGL), сплющенные в 512x384, с вклеенными шаттлом
и спутником, фильтр nearest. Теперь - HD, по актам и с яркостью из JSON.

### Решения (аргументы в скобках)
- Задник - только рельеф и звёзды. Всё рукотворное и всё, что светится, -
  поверх: корабль и спутник - объекты (шаг 2), Земля - эффект-глобус,
  огни - маячки (шаг 3). (Земля, нарисованная в четырёх генерациях, - это
  четыре разные Земли; фаза у эффекта - число, а не новая генерация.)
- Кулисы, не перспектива: камера на уровне земли смотрит горизонтально,
  слои параллельны экрану, пол - ровная полоса. (Первая генерация с
  посадочной площадкой рисовала плоскость земли вглубь и спорила с
  видом сбоку.) Исключение - экран 2 уровня 2, край обрыва: камера
  смотрит вниз, неба нет, как в 2008.
- Солнца в кадре нет: оно встаёт из-за хребта, а объект поверх задника
  перекрыл бы горы. Время суток рассказывает свет на рельефе: уровень 1 -
  ночь (1-7), предрассветный час (8-11), восход (14-17); уровень 2 -
  яркий день (выход после босса), обрыв, подземелье.
- Фаза Земли: освещённая сторона смотрит на Солнце. Солнце слева, Земля
  справа - к восходу Земля полнеет, а не худеет в серп. Позиция Земли
  одна на весь уровень (Луна повёрнута к Земле одной стороной).
- Рисуем нормальной яркости, приглушаем кодом: `tint` на записи
  `backgrounds`, процент на канал, через SDL_SetTextureColorMod (так уже
  приглушено небо меню, SkyShade). (Тёмная картинка в 8 битах даёт
  ступени в градиентах неба; число в JSON правится без генерации и без
  перекомпиляции.) Тинт на запись, не на уровень: акты разной яркости.
  Ночь уровня 1 сдвинута в синий (земной свет), день уровня 2 почти
  нейтральный.
- Дымка у горизонта запечена в ночные задники уровня 1 (синяя полоса
  смешиванием screen, 45/40/35% по актам). На Луне дымки нет, но без неё
  пропадает воздушная перспектива, а на экране 17 шипы сливались с
  хребтами того же тона. Дню и подземелью она не нужна.
- Линейный фильтр - только на кэш задников (HD ужимается в окно меньше
  1080p, nearest давал бы зерно; тайлам и спрайтам nearest остаётся).
- 1440x1080 - игровое поле экрана 1080p один в один.
- Подземелье уровня 2: одна скала на экраны 3-9, "глубже" - вторая
  запись той же картинки с меньшим тинтом. Замер по альфе тайлов: задника
  видно 35-54% на 3-5, 12-30% на 6-8, 0% на 9 - ледяные жилы (6-8) и
  лавовая трубка (9) отменены, их бы не увидели.
- `_scr0` удалён: это `_scr1` с вклеенным шаттлом (дифф только в его
  рамке).

## Сессия: статические объекты уровня, v3.0.12 (2026-09-30)

Шаг 2 релиза 3.0, сделан раньше эмиттера (шаг 1): объекты от него не
зависят, а экран 1 без шаттла стоял пустым с 3.0.11. Корабль и спутник
вынуты из задников 2008 в слой объектов; код не знает, что именно рисует.

### Решения (аргументы в скобках)
- Место объекта - `x`, `y` левого верхнего угла и `width`, всё в единицах
  экрана; высота из пропорций арта. (Клетка 32 - шаг 11 px на 1080p,
  опоры корабля на пол так не поставить; полный прямоугольник даёт
  независимые w и h, и одна опечатка сплющивает арт. Ширина в единицах не
  зависит от плотности картинки: перерисованный в другом разрешении
  корабль остаётся на месте.)
- Яркость - тот же `"tint": [r, g, b]`, что у задников, тот же парсер;
  три равных числа - чистая яркость. (Одно слово для одной вещи во всём
  JSON уровня; синий сдвиг ночи задникам уже понадобился.)
  `TBackdropTint` стал `TColorTint`, `ReadBackdropTint` - `ReadTint`:
  старые имена врали бы про объекты.
- Модель - в Levels.Defs (`TLevelObject`, `ParseObjects`, свойство
  `Objects`), а не отдельным юнитом Levels.Objects, как было в плане.
  (Объекту нужны ридер тинта и ELevelError из Levels.Defs, а Levels.Defs
  владеет списком - отдельный юнит потребовал бы третий юнит под тинт;
  машинерии вышло бы больше, чем самих объектов: запись и один метод.)
- Отрисовка - свой юнит Core/Render.Objects (`TObjectScreenRenderer`), как
  в плане. Все спрайты разрешаются в конструкторе (опечатка в имени
  падает на загрузке уровня, а не на экране 14).
- Пересчёт процентов в color mod вынесен в `Render.Sprites.TintTexture`
  (задники и объекты - два клиента одной формулы).
- Соглашение `<assetsDir>-<вид>.mset` - в одном месте, `OpenLevelArtSet` в
  dpr (у задников появился второй клиент). Набор объектов открывается,
  только если уровень что-то ставит (уровню без объектов пустой набор не
  нужен).
- Слой - между задником и тайлами, канал тряски scWorld. (Корабль стоит
  на полу из тайлов; неподвижный над трясущимся полом он бы парил.)

  релиза. Поле появится с первым объектом перед тайлами.)
- Плотность арта - как у задника, 1440 px на 512 единиц: корабль 1974 ->
  844x308 (300 единиц), спутник 1305x1206 -> 172x159 (61 единица).

  сжатии в 2.3 раза даёт зерно.)
- Под прозрачными пикселями исходников был чистый чёрный - залит цветом
  ближайшего края. (Линейный фильтр в окне меньше 1080p подмешивает
  соседний пиксель, на краю вышла бы тёмная кайма.)
- Места сняты с макетов подгонкой (расхождение 0.6 из 255): корабль
  `4, 244, 300` на экране 1, опоры на юнит уходят за тайлы пола; спутник
  `213, 39, 61`.
- Корабль без тинта (на макете он на полной яркости). Спутник темнее:
  `[70, 72, 78]` на 14-17 уровня 1 (холод под предрассветный задник),

- Спутник стоит в одной точке на всех 14-17, как в заднике 2008, - едет
  за героем, как луна за окном поезда. Принято.
- Спутник лежит в обоих наборах объектов (по соглашению у каждого уровня

## Сессия: динамические объекты, маячок, v3.0.13 (2026-09-30)

Первая половина шага 3 релиза 3.0, опять раньше эмиттера (шаг 1): маячку
частицы не нужны, он рисуется светом Render.Glow. Динамический объект -
то, что расставляется как статический объект, но живёт от тика к тику.
Три лампы: синяя на киле корабля (экран 1 уровня 1), красная барахлящая
на антенне спутника (14-17 уровня 1), та же умирающая на экране 1
уровня 2.

### Решения (аргументы в скобках)
- Один абстрактный предок `TDynamicObject`, и ВСЕ виды - в одном юните
  `Core/Levels.Dynamics`, вместе с парсером. Переопределяет план релиза
  (там был юнит на эффект). Новый вид - класс, слово в `DynamicKindIds`
  и ветка в `CreateDynamic`.
- Предок держит и читает общее - `screen` или `parent`, `x`, `y`, `tint`
  (как у статики) - и сам прибавляет смещение к началу отсчёта: наследник
  получает в `DrawAt` готовую точку и знает только свои свойства, `Tick` и
  отрисовку.
- Родитель по образцу VCL, только система координат: без родителя объект
  прибит к точке экрана (`screen` обязателен), с родителем x/y считаются от
  левого верхнего угла родителя, а `screen` запрещён - экран решает
  родитель. Объект показывается везде, где стоит родитель (спутник на
  14-17 - одна картинка, и лампа едет с ним).
- Родитель пока - только статический объект по тегу: у объектов появилось
  поле `tag`. Монстр и герой как родители - вместе с дымом.
- Где стоит объект, решает `Render.Dynamics` (`TDynamicScreenRenderer`) один
  раз при загрузке: статические объекты не двигаются. Двинется родитель -
  стоянка станет запросом на каждую отрисовку там же; предок и виды этого
  не заметят.
- Секция JSON - `"dynamics"`, не `"effects"` из плана (Земля в небе - не
  эффект, а тоже динамический объект).
- Слой - сразу после статических объектов, до тайлов, канал тряски scWorld
  (лампа на корабле гаснет за героем, проходящим мимо).
- Лампы тикают на любом экране и переживают рестарт: владелец - `TLevel`,
  уровень при смерти не перечитывается (вернулся - лампа в середине ритма,
  а не с начала).
- Тинт маячка - цвет света: белая текстура свечения, тинт в процентах
  через `PercentToColorMod` (стал публичным в Render.Sprites) - то же
  слово, что у задников и объектов.
- Маячок из четырёх слоёв: горячее ядро (тинт с примесью белого), ореол,
  засвет вокруг (света на окружающее), на пике - блик с четырьмя шипами
  (`glint`); между вспышками стекло тлеет на 8% (лампа, а не дырка).
- Режимы `blink`: steady, pulse, flash (резкий фронт, экспоненциальный
  спад), double, faulty (цикл на 8 слотов: держит / проседает / гаснет),
  dying (на каждом цикле новая тусклая яркость 5-40%, частота 14 -
  мельтешение садящейся батарейки). Частота - в секунду игрового времени
  (авиационная норма заградительных огней 40-100 вспышек в минуту).
- Случайность faulty и dying - `SlotRoll`: свой `TXorShift` от номера слота
  и сида (`Random` не трогаем - он кормит таблицу спавна босса). Чистая
  функция номера: кадр между тиками не спорит с тиком. Сид - позиция в
  десятых юнита, лампы в разных точках барахлят вразнобой.
- Лучи старбёрста - два свойства: `rays` (длина луча от центра, 0 = нет) и
  `rayIntensity`. Новая форма `gsStarburst` в Render.Glow: крест тоньше шипов
  флейра и медленнее гаснет, текстура 256 px (волосу нужны пиксели поперёк).
  В покое луч держит 60% длины, вспышка дотягивает его до полной.
- На спутнике `glint` обнулён: два креста на одной лампе спорят.

### Попутно
- `TColorTint` и `ReadTint` уехали из Levels.Defs в свой юнит
  `Core/Levels.Tint` (Levels.Defs использует Levels.Dynamics, тинт нужен
  обоим - без выноса цикл юнитов). Ошибка формы тинта - теперь
  `ETintError`, не `ELevelError`.
- У `TLevel` появился деструктор - владелец списка динамических объектов.
- Проверки на загрузке (`CheckDynamics`): прибитый объект вне списка
  экранов, тег родителя, которого не носит ни один объект, два объекта с
  одним тегом на одном экране.

### Находки
- Купол на киле корабля нарисован красным стеклом; синяя вспышка поверх
  него на пике уходит в бело-голубой.
- Кода без компилятора: прочитан отдельным агентом как компилятор, ошибок
  сборки не нашлось; замечания по комментариям и `const` исправлены.

### Открытое
- Коэффициенты (засвет, ядро, блик, лучи, частоты) подобраны в
  симуляции на Python - подкрутить вживую.
- Дым (Smoke) - на эмиттере шага 1, с родителем-монстром по тегу и
  действием события startEffect.
- Земля (`globe`) - тонкий наследник в Levels.Dynamics, рисование в
  Core/Render.Globe (вынос Menu.Globe) - принято.

### Коммиты
Add dynamic objects with a beacon (3.0.13); Hang beacons on the level 1
and 2 satellites and the ship; Update the docs for dynamic objects. Тег
3.0.13 - на последнем.

## Сессия: дым и газ, события интенсивности, v3.0.14 (2026-09-30)

Второй вид динамических объектов - `smoke` (`TSmoke` в Levels.Dynamics).
Газ из пробоин спутника на 14-17 уровня 1, та же утечка на экране 1
уровня 2 почти иссякла; босс уровня 1 начинает дымить перед яростью,
в ярости перестаёт, перед смертью дымит сильнее прежнего, с огнём.

### Опыт, на который опирались
- Современный дым в 2D - частицы с мягкими рваными текстурами (несколько
  форм, случайный поворот и вращение - повторов не видно), рост за жизнь
  (сначала быстро), проявление и затухание по кривой, цвет за жизнь,
  сопротивление, тяга, шум-завихрение (curl noise), эмиссия по
  расстоянию у движущегося источника. Дым - альфа-блендинг (закрывает),
  огонь и свет - аддитив (прибавляет).
- Реализм на Луне: воздуха нет. Газ из пробоины уходит конусом, не
  тормозит, не поднимается и не клубится - гаснет, расширяясь (водные
  сбросы с орбиты - квазиконическое облако около 10 градусов, частицы
  летят со скоростью выброса). Поэтому у спутника lift 0 и drag 8%.
  Дым босса тоже без подъёма: остаётся там, где выпущен, - движущийся
  босс оставляет шлейф.

### Решения
- Смок живёт в Levels.Dynamics рядом с маячком (правило "все виды в одном
  юните"). Частицы - в новом Core/Effects.Emitter (`TParticleSwarm`:
  рождение, дрейф с drag и тягой, старение, `ShiftFrame`), без внешнего
  вида: смотреть и мешать - дело владельца. Это и есть шаг 1 плана
  релиза; Menu.Embers переводится на рой отдельно.
- Клубы генерируются при загрузке уровня (Core/Render.Puff): четыре
  формы из фрактального шума значений, контур изогнут тем же шумом,
  пятнистая яркость внутри. Альфа-блендинг, линейный фильтр; поворот -
  новый биндинг `SDL_RenderCopyExF` (+ `TSdlFPoint`).
- Свойства смока в JSON - всё, что захочется крутить в редакторе: tint и
  endTint (цвет при рождении и при смерти; `ReadTint` получил ключ),
  intensity, rate, life, size, endSize, opacity, angle (против часовой
  от "вправо", 90 = вверх), cone, speed, drag, lift, wind, turbulence,
  spin, flow (steady / gusty / puffs), frequency, heat. В JSON секунды и
  проценты, в коде тики и доли.
- Вылетевший клуб стоит на экране, а не едет с родителем: частицы в
  системе точки выброса, при движении родителя рой сдвигается обратно
  (`ShiftFrame`). Новые клубы рождаются вдоль отрезка, пройденного за
  тик: быстрый босс (6 единиц за тик в ярости) даёт шлейф, а не бусы.
- Завихрение - функция тока из двух дрейфующих волн: поток без
  источников и стоков, дым вьётся, не собираясь и не рвясь. Хватка
  растёт с возрастом клуба: свежая струя летит прямо, старый дым вьётся.
- Intensity множит темп и, корнем, плотность клуба - плотность
  фиксируется при рождении, так что выключенный источник не гасит уже
  вылетевший дым, тот рассеивается сам.
- `heat`: свежий клуб подмешивает огненный цвет и несёт аддитивное
  свечение первые 30% жизни - горящий босс.
- Intensity - общее свойство предка (`TIntensityFade`, плавный переход за
  ticks), маячок тоже его слушается. Единственное, что события меняют на
  ходу.
- Родитель-монстр: тег, которого не носит ни один статический объект,
  ищется среди монстров каждый тик через колбэк игры (`TLocateMonster`,
  `LocateMonster` в dpr) - поле рождается заново на рестарте, ссылку не
  держим. Пока монстр мёртв или пропал - выброса нет (взорванный босс
  исчезает, дым из воздуха был бы враньём).
- Слой: `layer` back (по умолчанию, со статическими объектами) или front
  (поверх монстров, под героем, канал тряски монстров). Дым босса - front.
- `FDynamics.Tick` переехал в Update после монстров и директора: иначе
  клубы выходят из места, где босс был тиком раньше.
- События: условия `livesBelow` (живой с тегом, жизней меньше lives) и
  `enraged` (живой с тегом в ярости - флаг TMonster.Enraged, у танка
  тоже), действие `intensity` (target - тег динамики, value - процент,
  ticks - за сколько). Для босса: livesBelow 150 - bossSmoke до 60% за
  2 с; enraged - bossSmoke в 0 сразу; livesBelow 30 - bossSmoke и
  bossBurn до 100% за секунду. Порог ярости абсолютный (80), поэтому
  пороги 150 и 30 работают на любой сложности (400/600/800 жизней).
- Смерть героя: `ReArm` директора откатывает цели intensity у
  перевзведённых событий (`RewindTagged`) - босс возрождается спокойным,
  дым в воздухе исчезает вместе с ним. Лампы и газ спутника не трогаются.
- Проверки загрузки: динамика разбирается до событий; цель intensity
  должна носить хоть одна динамика; тег родителя - на объекте или на
  сущности, не на обоих; две сущности с тегом-родителем на общем грейде
  сложности - ошибка (непересекающиеся грейды - один монстр на
  сложность).

### Настройки в уровнях
- Уровень 1, спутник: главная утечка из пробоины (x 36.9, y 31.2, угол
  -15, конус 32), нижний край пробоины (34.8, 39.7, угол -50),
