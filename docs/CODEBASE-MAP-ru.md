# Moon 2D - карта кодовой базы

Справочник по проекту. Назначение: имея этот файл плюс описание задачи, сразу
понимать, какие файлы открывать, без повторных раскопок репозитория.

Репозиторий: `https://github.com/rm3g25/moon2d/`, Delphi 10.3+ (inline var) +
SDL2, Win32. Логика в пространстве 512x384 игровых единиц (16x12 клеток по 32),
тайловая графика 64 px, фиксированный тик 33 Гц, уровни по экранам (без
скролла).

Перегенерировано на `v3.0.3`, поправлено по `v3.0.19` (раскладка по папкам
случилась между 3.0.8 и 3.0.9) и на `v3.0.19` сверено с кодом посекционно.
Где карта и код расходятся, прав код.

## Раскладка исходников

Юниты лежат в четырёх папках под корнем; `Moon2D.dpr`, `.dproj` и `Moon2D.inc`
остаются в корне, каждый юнит подключает его (`{$I ..\Moon2D.inc}`; из
`Game/Events/` - `{$I ..\..\Moon2D.inc}`).

- `Core/` - то, что делят редактор уровней и инструменты: привязки SDL, наборы
  спрайтов, отрисовка (с тряской), кисть, эффекты (рой частиц, обломки),
  модели уровня/монстров/конфига/языка,
  пространство кадра и экрана. **Core не использует ни одного юнита вне
  Core** - инструмент или редактор, ссылающийся только на `Core/`, перестаёт
  собираться в тот же день, когда правило нарушено.
- `Game/` - сама игра: герой, монстры и диск босса, пули, взрывы, звук, хост
  цикла, словарь бонуса,
  церемония хеншина, версия. `Game/Events/` исполняет события уровня.
- `Hud/` - всё, что рисуется поверх игрового поля, плюс экран рассказа и общая
  для них печатная машинка.
- `Menu/` - главное меню и его небесная установка.

Game, Hud и Menu - соседи над Core и могут пользоваться друг другом. События
уровня из JSON разделены по этому правилу: модель и парсер (`Levels.Events`)
лежат в `Core/`, потому что их будет писать редактор; исполнитель
(`Events.Director`) - в `Game/Events/`. Два юнита в `Core/`
пока носят префикс `Game.` (`Game.Config`, `Game.Space`) - слой определяет
папка, а не префикс.

Направление зависимостей (примерно снизу вверх):
`Sdl2.Core` / `Sprites.Sets` -> `Sdl2.Image` -> `Render.*` / `Audio` / `Game.Config` /
`Game.Bonus` / `Game.Space` / `Localization` / `Render.Brush` ->
`Levels.Tint` / `Levels.Events` / `Effects.Emitter` / `Render.Puff` /
`Effects.Debris` (рисует через `Render.Glow`) ->
`Render.Globe` -> `Levels.Dynamics` (рисует через `Render.Glow`,
`Render.Puff` и `Render.Globe`) ->
`Levels.Defs` /
`Monsters.Defs` / `Hud.Vitals` / `Hud.Charge` / `Hud.Typewriter` ->
`Hud.Terminal` / `Hud.Briefing` ->
`Bullets` / `Monsters.Disc` (диск босса: над `Render.Sprites` и
`Monsters.Defs`, сенсор - через `Render.Glow`) -> `Hero` /
`Monsters` / `Hud.Messages` / `Render.Tiles` / `Render.Objects` /
`Render.Dynamics` / `Game.Explosions` (над `Effects.Debris`,
`Levels.Dynamics` и `Monsters.Defs`) -> `Hud.Marks` /
`Game.Henshin` / `Events.Director` -> `Moon2D.dpr`, который ведёт и
`Game.Loop` (хост: только над `Sdl2.Core` и `Game.Config`, ни одного
игрового юнита не знает). Небесная установка меню
сбоку: `Render.Brush` -> `Render.Glow` -> `Menu.Starfield` / `Menu.Embers` ->
`Menu.Logo` -> `Menu` (с `Menu.Globe` - тонкой луной над `Render.Globe`).

## Юниты игры

### `Core/Sdl2.Core.pas` (~395 строк)
Рукописные биндинги SDL2. Классов нет - константы, записи, объявления
`external` к `SDL2.dll`.
- **Константы**: флаги инициализации, флаги окна (включая `SdlWindowHidden` для
  офскрин-инструментов), флаги рендерера, режимы доступа к текстурам (включая
  `Target`), хинты (`SdlHintRenderDriver`, `SdlHintRenderScaleQuality`),
  идентификаторы событий, флаги отражения, формат пикселей
  `SdlPixelFormatAbgr8888`, режимы блендинга (`None`, `Blend`, `Add` -
  последний для бликов HUD), режимы масштабирования
  (`SdlScaleModeNearest`/`Linear` - фильтр на текстуру), базовые сканкоды
  (Return, Escape, Ctrl/Alt, Space, стрелки; буквы, нумпад и дебажные
  клавиши - константы в dpr).
- **Записи**: `TSdlRect`, `TSdlFRect`, `TSdlPoint`, `TSdlFPoint`,
  `TSdlRendererInfo`,
  `TSdlVersion`, `TSdlSurface` (частичное зеркало - только ведущие поля),
  `TSdlKeysym`, `TSdlKeyboardEvent`, `TSdlMouseMotionEvent`,
  `TSdlMouseButtonEvent`, `TSdlEvent` (вариантная, ветка-паддинг на 56 байт).
- **Импорты**: жизненный цикл окна и рендерера, вызовы отрисовки
  (`SDL_RenderCopy/F/Ex/ExF`, заливка, очистка, present), поверхности + color key +
  конвертация формата, текстуры (включая target-текстуры, потоковые
  `SDL_LockTexture`/`SDL_UnlockTexture` - глобус, `SDL_SetTextureScaleMode`
  на текстуру, color и alpha mod и
  `SDL_RenderReadPixels` - используется в TitleCard), события,
  `SDL_ShowCursor`, `SDL_GetRendererInfo`, `SDL_GetVersion`, тайминг
  (`SDL_GetPerformanceCounter/Frequency`, `SDL_Delay`), `SDL_SetHint`,
  `SDL_RenderSetLogicalSize`, `SDL_RWFromMem`.
- **Хелперы**: `SdlText(string)->UTF8String`, `SdlErrorText`.
- Лезть сюда, если: нужна новая функция SDL, вопросы по обработке событий или
  по ABI.

### `Core/Sprites.Sets.pas` (~445 строк)
Контейнер наборов спрайтов `.mset`: JSON-манифест, за ним все картинки подряд.
Читается игрой, упаковщиком и (позже) редактором уровней - один юнит, три
вызывающих. Вся графика игры приходит из наборов, россыпь картинок больше не
поставляется. `SetQualifier` (':') живёт здесь же - редактор и упаковщик читают
тот же синтаксис.
- **Константы**: `MsetVersion=1`, `SetQualifier=':'`. Имена полей манифеста -
  константы (`KeyId`, `KeySprites`, `KeyOffset`...): опечатка в литерале
  компилируется.
- **Записи**: `TSpriteEntry` (имя, описание, offset, size - смещение от начала
  блока картинок, не от начала файла), `TSpriteSequence` (имя, описание,
  кадры), `TMsetHeader` (packed: магия, версия, размер манифеста), `TMsetMagic`
  (именованный тип - анонимный `array[0..3] of AnsiChar` не присвоится другому
  такому же).
- **`TSpriteSet`** - чтение. При открытии разбирается только манифест, байты
  картинок приходят по требованию: `ReadSprite(name)`, `Contains`,
  `SequenceFrames`; свойства `Id`, `Description`, `Entries`, `Sequences`.
- **`TSpriteSetWriter`** - запись. `AddSprite`/`AddSpriteFile`, `AddSequence`,
  `SaveToFile`. Смещения раздаются при сохранении в порядке добавления; запись
  детерминированная, поэтому неизменившийся набор пересобирается байт в байт.
  Ловит дубли имён и последовательности, ссылающиеся на отсутствующие кадры.
- Спека формата: `docs/MSET-FORMAT.md`.

### `Core/Render.Sprites.pas` (~530 строк)
Кэш текстур + низкоуровневая отрисовка спрайтов. Здесь же живут константы
размеров.
- **Константы**: `SpriteSetsDir` ('sprites\'), `SpriteSize=32`, `TileSize=32`
  (игровые единицы!), `TileArtSize=64` (пиксели текстуры!), `FramesAlive=8`,
  `FramesDeath=8`. Разделение 32 против 64 - та самая дисциплина систем
  координат в коде.
- **`TSpriteCache`** - словарь `набор:имя -> PSdlTexture`, ленивая загрузка из
  наборов, подключённых через `AttachSpriteSet` (не владеет - освобождает тот,
  кто открыл); `Get(name)` отдаёт текстуру, загружая картинку при первом
  обращении. Разрешение: квалифицированное имя (`common:pustota`) идёт только
  в названный набор; голое - в первый подключённый, который его содержит;
  **имени, которого нет ни в одном подключённом наборе, соответствует
  `ESpriteError`** - отката к папке больше нет. Путь и расширение отбрасываются
  при поиске, поэтому написания 2008 в палитрах (`level1\doom1.png`)
  по-прежнему разрешаются. `SourceOf(name, out bare)` - то же разрешение без
  текстуры: набор и имя, как он его знает (небесный глобус читает через него
  карты). `AmbiguousNames` докладывает голые имена,
  встречающиеся в нескольких наборах - они разрешились бы порядком объявления,
  ради чего квалификатор и заведён. Color key: по умолчанию чёрный
  (`SetColorKey` меняет цвет, `DisableColorKey` снимает ключ - так делают
  кэши задников, объектов и диска). `EnableLinearFilter` даёт текстурам кэша
  линейный фильтр поверх глобального nearest - для арта плотнее логического
  экрана (HD-задники), где nearest при уменьшении превращает детали в зерно.
  Оба действуют на текстуры, загруженные после вызова.
- **`LoadImageSurface(spriteSet, name)`** (свободная функция) - единственное
  место, которое превращает хранимые байты в поверхность. Возвращает `nil` для
  пустого набора или неизвестного имени; формулирует ошибку вызывающий, потому
  что только он знает, для чего была картинка.
- **`TAnimSet`** (запись) - массивы текстур `Alive[0..7]` и `Death[0..7]`;
  `IsLoaded`. Собирается **`LoadAnimSet(cache, spriteSet)`** из
  последовательностей `alive` и `death` манифеста, каждая проверяется на ровно
  восемь кадров - `TAnimSet` это контракт 2008 с фиксированными массивами.
- **`TintTexture(texture, r, g, b)`** (свободная функция) - color mod по
  каналам в процентах, 100 = как нарисовано. Текстура держит его до
  следующего вызова, поэтому картинку, которую делят разные тинты, красят
  перед каждой отрисовкой. Через неё тонируются и задники, и объекты уровня.
  **`PercentToColorMod(percent)`** - один канал этого пересчёта, открыт для
  того, кто передаёт цвет дальше, а не ставит его на текстуру (через него
  тинт маячка становится цветом свечения).
- **`TSpriteRenderer`** - рисует в игровых единицах: `DrawCell` (спрайтовая
  сетка), `DrawTile` (тайловая сетка, кроп верхних левых 64x64 воспроизведён из
  `sttextures.pas`), `Draw` (свободная позиция, опция зеркала), `DrawRect`,
  `DrawRotated` (рука с оружием), `DrawTurned(texture, center, side, angle,
  level = 1)` - квадрат любого размера с центром в дробной точке, повёрнутый
  по часовой, с заданной непрозрачностью; дробные координаты до самого SDL
  (`SDL_RenderCopyExF`), так что нарисованное между тиками не прыгает по
  логическим единицам - через него рисует слои диск босса. На каждом вызове
  ставит текстуре alpha mod. **`Origin`** (`TSdlPoint`) сдвигает каждый из
  них - точка входа тряски экрана; здесь его никто не сбрасывает, вызывающий
  ставит его перед каждым слоем, а неподвижные слои (задник, курсор, HUD)
  рисует при `NoShake`. Конструктор берёт логический размер и ставит его
  рендереру (`SDL_RenderSetLogicalSize` - dpr передаёт кадр из
  `Game.Space`).

### `Core/Sdl2.Image.pas` (~70 строк)
Биндинги SDL2_image, delayed-импорты по образцу `Audio.pas`. `IMG_Load_RW`
заменил `SDL_LoadBMP_RW` во всех точках загрузки. `EnsureImageLib` вызывается на
старте и падает внятным сообщением, если DLL нет: в отличие от опционального
миксера, отсутствие графики фатально.

### `Core/Render.Tiles.pas` (~100 строк)
- **`TTileScreenRenderer`** - рисует один экран двумя слоями в порядке,
  который задаёт вызывающий: `DrawBackground` (спрайт-задник экрана через
  `FBackgroundCache`), затем `DrawTiles` (индексы палитры из `TLevel` через
  `FTileCache`). Два вызова и никакого общего: задник стоит, пока тайлы
  трясутся. Оба кэша
  наполняются композиционным корнем из `.mset`-наборов, и ни одним из них юнит
  не владеет. `DrawBackground` ставит тинт смены (`TintTexture`) перед каждой
  отрисовкой, а не при загрузке: одну картинку могут делить две смены с
  разными тинтами.

### `Core/Render.Objects.pas` (~80 строк)
- **`TObjectScreenRenderer`** - рисует объекты уровня на экране (свободный
  арт, `TLevelObject`) в порядке файла, каждый в своём прямоугольнике со своим
  тинтом. Конструктор заранее разрешает все спрайты и считает все
  прямоугольники (высота из пропорций арта), так что спрайт, которого нет в
  наборе, падает на загрузке уровня, а не на экране, который его показывает;
  дальше `Draw(screen)` только идёт по списку. Кэш даёт композиционный
  корень: без color key (честная альфа PNG - чёрное стекло и тени пропали бы
  через ключ), с линейным фильтром, из собственного
  `<assetsDir>-objects.mset` уровня (когда уровень его поставляет) и общих
  наборов `objectSets`; юнит им не владеет.

### `Core/Render.Dynamics.pas` (~300 строк)
- **`TDynamicScreenRenderer`** - выводит динамические объекты уровня
  (`Levels.Dynamics`) на экран. Владеет текстурами `TDynamicCanvas`
  (свечения точка, флейр, старбёрст - `Render.Glow`; клубы дыма -
  `Render.Puff`) и одалживает ему кэш арта объектов уровня (`Art`); делает
  их при загрузке уровня; сами объекты
  принадлежат уровню. После канвы каждый объект делает себе то, чем рисует
  (`Acquire`, у небесного глобуса - `TGlobe`); деструктор отпускает это (`Release`) до
  канвы, так что все SDL-текстуры умирают раньше рендерера. На каждый объект - `TPlace`: стоянки (экран + начало
  отсчёта), флаг монстра, жив ли родитель, ведущий экран. Прибитый стоит в
  (0, 0) на своём экране или на каждом экране своего отрезка `screens`; под статическим объектом - на каждом экране, где
  стоит тот объект, в его левом верхнем углу; решается один раз - статика
  не двигается. Тег, которого не носит ни один объект, - монстра: его
  стоянка ищется каждый тик через **`TLocateMonster`** (`reference to
  function(tag, out TParentStand)`: экран, левый верхний угол спрайта, жив
  ли; у монстра, который вращается, ещё `Spins` и `TParentSpin` - его
  `TSpinPose` (ось на экране, угол в градусах по часовой) сейчас и тик
  назад плюс место оси от левого верхнего угла спрайта) - поле рождается
  заново на рестарте, ссылку не держим; пропавший
  монстр оставляет последнюю стоянку. **`OriginOf(place, stand, alpha)`** -
  угол, от которого считает объект: угол стоянки или - у расстановки с
  `Turns` под вращающимся родителем - то место, куда её точка довернулась
  вокруг оси, на долю alpha между двумя позами: лампа едет на диске босса
  между тиками ровно так, как рисуется сам диск. `Tick(screen)` тикает все
  объекты на
  любом экране (лампа держит ритм и за кадром) от стоянки на экране героя,
  иначе от первой (в позе, до которой тик только что дошёл, - `ThisTick`);
  ведущая стоянка на другом экране - прыжок
  (`ForgetOrigin`), а не полёт. `Draw(screen, origin, alpha, layer)` рисует
  те, что на экране, в одном слое (`dlSky` / `dlBack` / `dlFront`); место с
  `Turns` не рисуется, когда родитель больше не жив (умирающий тоже), -
  вращаться больше не с чем.
  **`Reseat`** - монстры родились заново (рестарт): каждое место, идущее
  за монстром, сразу находит родителя и забывает начало отсчёта, так что
  кадр до следующего тика не покажет его на старой стоянке. `Canvas` -
  текстуры, одолженные дыму подбитых машин и взрывам (`Game.Explosions`).

### `Core/Render.Shake.pas` (~110 строк)
Тряска экрана как один метр травмы на всю игру, читаемый обратно как сдвиг
отрисовки по слоям. Только рендер: арифметика мира сдвига не видит.
- **`TShakeChannel`** = (`scWorld`, `scHero`, `scMonsters`) - мир (тайлы,
  пули) дёргается одним куском; герой и монстры едут вместе с ним плюс своя
  небольшая добавка (`FigureJitterRatio=0.25`), чтобы фигуры выглядели
  отклеенными от земли.
- **`TScreenShake`** - `AddTrauma(amount)` (мягкое насыщение `T += A*(1-T)`:
  цепочка бочек ползёт к потолку и не упирается в него), `Tick` (раз в
  логический тик: линейное остывание `TraumaDecayPerTick=0.03`, затем свежий
  бросок всех трёх сдвигов - амплитуда `T^2*MaxShakeOffset(8)`, так что одна
  бочка едва заметна, а босс - потолок), `Offset(channel)`. Свой поток
  xorshift, не `Random`: тот кормит спавн-таблицу босса. `NoShake` - константа
  нулевого сдвига.
- Дозы живут у того, кто трясёт (константы `*Trauma`: взрывы и бонусы - в
  dpr, кольца и финал хеншина - в `Game.Henshin`), не здесь: что и насколько
  трясёт - политика игрового потока, этот юнит - механизм.

### `Core/Render.Font.pas` (~405 строк)
Растровый шрифт: квадратный атлас с сеткой глифов 16x16 (раскладка CP1251).
Атлас 2008 - 448 px (клетки по 28 px); перерисованный может быть любым
квадратом со стороной, кратной 16, - размер клетки читается из картинки при
загрузке.
- **Константы**: геометрия атласа (`FontAtlasSize`, `FontGridCells`,
  `FontCellPx`) + дословные метрики глифов 2008, выведенные из NDC-математики
  оригинала (`LegacyColumnWidth`, `SmallGlyphWidth/Height`,
  `BigGlyphWidth/Height`, `BigAdvanceRatio=0.8` - перекрытие 20%,
  `BigGlyphAspect`).
- **`TFontAtlasOrientation`** = (`faUpright`, `faRotatedCw`) - фикс ориентации
  атласа.
- **`TFontFiltering`** = (`ffLinear`, `ffNearest`, `ffLinearSmallOnly`) - как
  фильтруется перерисованный атлас; ставится через `TMoonFont.Filtering`
  (dpr выбирает `ffNearest`; N листает его в сборке с DEBUGKEYS).

  `DrawSmall`, `DrawBig`, `DrawScaled`

Модель данных уровня + JSON-парсер. Игровой логики нет.

  либо `{"normal":..,"hard":..,"wild":..}`; `Uniform`, `ForGrade`.
- **`TEntityTriggers`** (запись) - `BigMessage`/`SmallMessage`/`HintText`
  (локализованные), `ChangeMusic`, перестановка героя по heroX/heroY

- **`TEntityPlacement`** (запись) - monsterId, экран (с единицы), x/y
  (спрайтовая сетка), spriteList, `Grades` (идиома doom-овских флагов
  сложности), overrides, triggers, `Tag` (метка расстановки для условий
  событий с тегом - `allDead`, `livesBelow`, `enraged` - и для динамических
  объектов, повешенных на монстра; '' = нет). `SpriteList` до сих пор несёт
  написание 2008
  `.mns` (`gravel.mns`); основа имени называет набор `.mset`, расширение
  отбрасывается при загрузке. Переименование поля - изменение данных, у него
  будет свой шаг.
- **`TBackgroundChange`** (запись) - fromScreen + image + tint
  (`TColorTint` из `Levels.Tint`).
- **`TLevelObject`** (запись) - свободный арт поверх задника: sprite (в
  `<assetsDir>-objects.mset` или общем наборе из `objectSets`), экран (с
  единицы), x/y (левый верхний угол) и
  ширина в единицах экрана, tint, `Tag` (имя для динамических объектов,
  подвешенных к нему; одна картинка на нескольких экранах несёт один тег на

  так что картинка никогда не растягивается. Коллизий нет - где стоит герой,
  решает только сетка.
- **`TLevel`** (класс) - разобранный уровень: тайлы `[экран][строка][столбец]`,
  строки коллизий `[экран][строка]` ('1' = стена), палитра тайлов, фоны,
  сущности, id/title/assetsDir/**spriteSets**/**objectSets**/music/introText, размеры сетки,
  число экранов. `SpriteSets` - наборы окружения в порядке разрешения, только
  тайлы; задники экранов идут по соглашению `<assetsDir>-backdrops` и там не
  появляются. `Objects` - свободный арт в порядке файла (поздний рисуется
  поверх раннего); приватный `ParseObjects` читает необязательную секцию
  `objects` и отказывает объекту вне списка экранов или с шириной ноль и
  меньше. `Events` - события уровня (`Levels.Events`) в порядке файла.
  Запросы: `TileAt`, `SolidAt`, `BackgroundFor` (смена целиком, побеждает
  последняя; `Image = ''`, если у уровня задников нет). `LoadFromFile`;
  динамика разбирается раньше событий - событие может назвать тег
  динамического объекта. Приватный `CheckEvents` отказывает событию вне
  списка экранов, событию, следящему за тегом, которого не носит ни одна
  расстановка, и (`CheckEventTargets` -> `CheckEventTarget`) действию
  intensity с тегом, которого не носит ни один динамический объект, и
  действию sun с тегом, которого не носит ни один глобус. `Dynamics` - динамические объекты
  (`Levels.Dynamics`); ими владеет уровень (единственный деструктор тут), и
  они переживают рестарт - лампа держит ритм, откатывается только то, что
  поменяло перевзведённое событие. Приватный `CheckDynamics` отказывает
  прибитому объекту вне списка экранов и отрезку `screens`, который идёт
  задом наперёд или выходит за список (`CheckDynamicScreens`), тегу родителя, которого не носит ни
  объект, ни сущность, тегу на тех и других сразу, двум объектам с одним
  тегом на одном экране и (`CheckMonsterParent`) двум сущностям с одним
  тегом на общем грейде сложности (ребёнок не поймёт, кто родитель).

### `Core/Effects.Debris.pas` (~610 строк)
Что разбрасывает взрыв, только украшение - ранят вееры осколков 2008, этот
юнит - нет. **`TDebrisField`** получает рендерер и **`TSolidProbe`**
(`reference to function(x, y): Boolean`, экранные единицы - игра даёт
`SolidUnderPoint`, так что юнит не знает уровня).
- **`TDebrisLook`** (запись) - один взрыв: `Shards`, `ShardSpeed`,
  `ShardSize`, `ShardCone` (ширина в градусах, по центру вверх),
  `RestSeconds`, `Sparks`, `SparkSpeed`; каждый кусок бросает значение
  между `MinShare` (0.35) от него и им самим.
- Осколки: `TShardState` = (`ssFlying`, `ssSliding`, `ssResting`).
  `FlyShard` двигает по одной оси за раз - стена разворачивает X
  (`WallBounce`), потолок Y; пол уходит в `LandShard`, который половинит
  шаг до линии пола и отскакивает (`FloorBounce` 0.35, `FloorGrip`) или,
  медленнее `RestSpeed`, опускает осколок скользить (`SlideShard`,
  `SlideGrip`; за краем пола снова летит) и лечь. Лежит `RestSeconds`,
  потом тает за `FadeTicks`. Цвет - `HeatColor`: белый жар -> красный
  уголёк -> голый металл за `CoolTicks`, пока горячий - гаснущее свечение
  `gsPoint`. Гравитация `ShardGravity` = 0.3 - падение вееров 2008.
  Осколок, родившийся в стене, выбрасывается.
- Искры: штрихи вдоль скорости (свечение `gsPoint`, растянутое
  `SDL_RenderCopyExF`, длиной в `StreakTicks` пути), от белого к красному
  за жизнь 5..14 тиков, гаснут о первую твёрдую точку.
- Формы: `ShardShapes` (4) рваных пластинки на 5..7 углов, согнутых один
  раз (светлая и тёмная половины), сглаживание 2x2 (`PixelCover`); белые,
  форма в альфе, альфа-смешение, линейный фильтр - генерятся в
  конструкторе, как клубы дыма.
- Потолки `MaxShards` 256, `MaxSparks` 512 - цепочка бочек вытесняет
  старейших. Свой `TXorShift` ("Boom"), никогда `Random`. `Burst`, `Tick`,
  `Draw(origin, alpha)` (чистая: позиция экстраполируется по скорости, как
  у дыма), `Clear`. `EDebrisError`.

### `Core/Levels.Tint.pas` (~70 строк)
- **`TColorTint`** (запись) - множители R/G/B в процентах, применяются при
  отрисовке картинки; `Neutral` = 100/100/100 (как нарисована).

### `Core/Levels.Dynamics.pas` (~1250 строк)
Секция `dynamics` JSON уровня: вещи, расставленные как статические объекты,
но живые. **Все виды живут в этом юните**: новый вид - класс здесь, слово в
`DynamicKindIds`, его слой в `DefaultLayers` и ветка в `CreateDynamic`.
- **`TDynamicPlacement`** (запись) - общее для всех видов: `Screen`,
  `screens` (JSON `[первый, последний]` - один объект на отрезке экранов,
  читается в `Screen`..`LastScreen`) или `Parent` (ровно одно - с
  родителем экраны решает родитель; родитель - тег статического объекта или
  монстра), `X`/`Y` (единицы экрана; с родителем - от его левого верхнего
  угла), `Tint`, `Tag` (имя, по которому его крутят события), `Layer`
  (`TDynamicLayer`: `dlSky` - сразу поверх задника, стоит, пока мир
  трясётся, - дальние вещи; `dlBack` - со статическими объектами, за
  тайлами; `dlFront` - поверх монстров, под героем; по умолчанию - слой
  вида), `Turns` (JSON `turns`: точка вращается вместе с родителем, который
  крутится, - лампа на диске босса; без родителя - ошибка на загрузке; под
  родителем, который не крутится, точка стоит на месте, но под любым
  монстром место с `turns` перестаёт рисоваться, когда монстр умирает,
  мёртв или пропал).
- **`TValueFade`** (запись) - значение и куда его ведут события: исходное,
  текущее, цель, шаг; `Settle`, `HeadFor(target, ticks)`, `Tick`.
  Интенсивность любого объекта, солнце небесного глобуса.
- **`TDynamicObject`** (абстрактный) - держит расстановку и интенсивность
  (`TValueFade`; JSON `intensity`, процент, по умолчанию 100). `Tick(originX, originY, parentAlive)`
  считает, насколько сдвинулось начало отсчёта с прошлого тика, шагает
  затухание и зовёт защищённый абстрактный `Advance(motionX, motionY,
  parentAlive)` вида; `FadeTo(level, ticks)`, `Rewind` (виртуальный: назад
  к интенсивности из файла, начало отсчёта забыто), `ForgetOrigin`
  (следующий тик не считает движения), `Origin` (от чего считал прошлый
  тик). Два конструктора: из JSON или с заданной интенсивностью (для
  объектов, которые игра делает сама). `Draw(canvas, originX, originY,
  alpha)` прибавляет X/Y к началу отсчёта и зовёт защищённый абстрактный
  `DrawAt`. Виртуальные `Acquire(canvas)` / `Release` - то, что вид делает
  себе для рисования (у предка пусто). Родитель - только
  система координат, как в VCL: он ничем не владеет.
- **`TDynamicObjects`** (`TObjectList<TDynamicObject>`) -
  `FadeTagged(tag, level, ticks)`, `RewindTagged(tag)`,
  `TurnSunTagged(tag, degrees, ticks)`, `AnyTagged(tag, kind = nil)`: то,
  что спрашивают события и проверки уровня.
- **`TDynamicCanvas`** (запись) - рендерер + текстуры свечения и клубов,
  которыми рисует каждый вид, + `Art` (кэш арта объектов уровня - свой
  набор и объявленные общие);
  текстуры делает и освобождает `Render.Dynamics`, `Art` ему передают, и
  он его переживает.
- **`TBeacon`** - сигнальная лампа: горячее ядро (тинт с примесью белого),
  ореол, засвет вокруг (`SpillScale`), блик с четырьмя лучами на пике
  вспышки, по желанию лучи старбёрста, вытягивающиеся со вспышкой
  (`RayRestReach`); стекло тлеет между вспышками (`EmberLevel`). Свойства в
  JSON: `blink` (`TBlinkPattern`: steady / pulse / flash / double / faulty /
  dying; по умолчанию flash), `frequency` (в секунду игрового времени),
  `intensity`, `glint`, `rayIntensity` (проценты), `size` (ширина ореола),
  `rays` (длина луча, 0 = нет). `faulty` - цикл нарезан на слоты, каждый
  держит, проседает или гаснет; `dying` - на каждом цикле новая тусклая
  яркость (5-40%); оба бросают кости через `SlotRoll` (свой `TXorShift`, не
  `Random` - тот кормит таблицу спавна босса), чистую функцию номера слота,
  так что кадр между тиками никогда с ними не спорит. Сид - позиция
  (`PlacementSeed`), так что лампы в разных точках барахлят вразнобой.
- **`TSmoke`** - дым, газ, пар: клубы рождаются в точке (с разбросом
  `SpawnJitter`, а у движущегося родителя - вдоль отрезка, пройденного за
  тик: шлейф, а не бусы), летят по `angle` в пределах `cone`, растут от
  `size` до `endSize` (сначала быстро), проявляются за `FadeInShare` и
  гаснут по `FadeOutPower`, цвет `tint` -> `endTint`, случайное вращение
  `spin`. Вылетевший клуб остаётся на месте экрана (`ShiftFrame`), его несут
  `drag`, `lift`, `wind` и завихрение - `Stir`, поток из функции тока двух
  дрейфующих волн, который держит клуб тем крепче, чем он старше
  (`TurbulenceGrip`): свежая струя летит прямо, старый дым вьётся. `flow`
  (`TSmokeFlow`): steady, gusty (темп качается шумом значений по времени,
  узлы через `frequency`, пол `GustFloor`), puffs (отдельные облака
  `frequency` в секунду). `heat` - свежий клуб подмешивает `FireColor` и
  несёт аддитивное свечение первые `HeatShare` жизни. Интенсивность множит
  темп и, корнем, плотность клуба (фиксируется при рождении - когда события
  выключают источник, вылетевший дым гаснет сам). Пока родитель-монстр
  мёртв или пропал, выброса нет. `Rewind` ещё и чистит рой (смерть
  перезапускает мир целиком). Частицы - `TParticleSwarm` из
  `Effects.Emitter`, рисуются через `DrawPuff`; в JSON единицы в секунду, в
  коде - за тик. Вид дыма - запись **`TSmokeLook`** в единицах JSON
  (`ReadSmokeLook` заполняет её из файла уровня, `TakeLook` переводит в
  тики); `CreateLook(placement, look, intensity, seed)` делает дым из кода -
  дым подбитых машин в `Monsters`, плюмы взрывов. `Exhausted` -
  источник погас и последний клуб растаял (тогда плюм взрыва
  освобождается).
- **`TSkyGlobe`** (вид `globe`) - тело в небе, по умолчанию Земля над
  Луной (или мёртвая Земля Селены, Проксима c): `TGlobe` (`Render.Globe`), который
  делается в `Acquire` из арта объектов (`map`, по умолчанию `earth`,
  разрешается как спрайт объекта - `sky:earth` называет набор;
  необязательный `night` - огни городов, в том же наборе, иначе
  `EDynamicError`) и освобождается в `Release`.
  Солнце идёт по дуге над экраном - `sun` в градусах: 0 левый горизонт, 90
  зенит, 180 правый горизонт, ниже нуля ещё не взошло; Земля висит на
  высоте `altitude` над горизонтом и на `azimuth` правее прямого взгляда
  (на 90 она на дуге солнца - там возможно затмение). `Relight` переводит
  их в вектор солнца в собственном виде Земли - фаза и наклон терминатора
  выходят как в настоящем небе: солнце на левом
  горизонте - половина, освещённая слева, ещё не взошедшее - больше
  половины, поднимающееся к Земле - серп. Солнце - `TValueFade`, его
  поворачивает действие события `sun` (`TurnSun`) - только вперёд: поворот
  назад игнорируется, так что событие, повторённое после смерти, не
  отменит утро. Глобус пересвечивается, когда солнце сдвинулось на
  `RelightStep` (0.05 градуса). Остальной JSON: `size` (диск поперёк в
  единицах экрана; x, y - центр), `brightness` (процент от
  `GlobeLook.Exposure`, больше 100 можно), `nightBrightness` (процент от
  `GlobeLook.NightGain`, 2.5 - огни городов в несколько текселей, им нужно
  больше, чем освещённой земле), `longitude` (меридиан, смотрящий
  на Луну), `tilt` (наклон верха оси влево), `atmosphere` (процент, 0 -
  без воздуха - мёртвая Земля Селены), `surface` (matte / regolith).
  Интенсивность - альфа глобуса, тинт - его color mod. По умолчанию в
  небесном слое.
- **`ParseDynamics(root, levelId)`** - читает секцию (нет секции - пустой
  список, владеет вызывающий); неизвестный вид, layer, blink, flow или
  surface, ни одного или больше одного из screen, screens и parent,
  кривая пара `screens`, число вне диапазона - `EDynamicError`
  (`ReadWord`, `ReadShare`, `ReadPositive`, `ReadReach`, `ReadScreens`).
- `LogicTicksPerSecond = 33` - частоты в секундах; логика идёт 33 тика в
  секунду.

### `Core/Render.Globe.pas` (~650 строк)
Небесное тело как освещённая сфера на CPU. **`TGlobe`** принимает набор
спрайтов, имя карты (equirectangular; ширина - степень двойки и вдвое
больше высоты), необязательную ночную карту того же размера и

из dpr, - крен и наклон оси,

цвет воздуха, яркость ночной карты).

  более грубый уровень вместо пропуска текселей) -> `BuildTables`

  земли она прячет (`Clear`) и плотность ореола.
- `Spin(units)`, `Face(longitude)`, `DestFor(cx, cy, diameter)` (квадрат,
  который ставит туда диск вместе с ореолом), `Draw(dest, tint, level)` -
  перерисовывает streaming-текстуру только после изменений (`PaintRow` ->

  каждый вещественный тип, и нетипизированный литерал рядом с Double

  четверти миллиона текселей на 33 Гц. Пользователи: `Menu.Globe` (луна
  меню), `TSkyGlobe` из `Levels.Dynamics`.

### `Game/Game.Loop.pas` (~385 строк)
Хост: окно и рендерер плюс цикл с фиксированным шагом.
- **`TGameApp`** (абстрактный) - `Update(dt)` (фиксированный),
  `Render(renderer, alpha)` (alpha - доля интерполяции),
  `HandleKey/MouseMove/MouseButton`, `RequestQuit` / `QuitRequested`.
- **`TGameHost`** - `Create(config, title)`: объявляет per-monitor DPI до

  ожидание бюджета кадра для пути без vsync. Ежесекундный fps в заголовке с

  `Moon2D.inc` он выключен. `EGameHostError`.
  `TKeyAction` = (kaDown, kaUp).

## Инструменты

### `tools/SpritePack/` - упаковщик наборов спрайтов (консоль)
Собирает и осматривает `.mset`. Обёртка над `Sprites.Sets` и больше ничего.
- **`SpritePackCli.dpr`** (~350 строк) - команды `pack` / `list` / `unpack`.
  `pack` берёт все PNG в папке в натуральном порядке (2 раньше 10); `--list`
  разбивает список спрайтов 2008 на именованные последовательности по его длине
  (16 строк -> alive+death, 24 -> walk+death+henshin, иначе одна группа,
  `frames`); `--id` называет набор (по умолчанию - имя папки).
  `unpack` пишет картинки плюс `manifest.json`, так что набор всегда можно
  разобрать.
- `unpack`, затем `pack` - не круговой путь: `pack` не читает
  `manifest.json` - спрайты ложатся в натуральном порядке, описания выходят
  пустыми, последовательности берутся только из `--list`. Набору с
  описаниями или ручным порядком (`boss1-disc`, `sky`, `level1-objects`,
  `level1-backdrops`, `ui`) нужен `TSpriteSetWriter` напрямую, пока нет
  SpritePack.exe; анимированному набору - заново написанный список спрайтов
  для `--list`. Скрипт
  `pack-sets.ps1`, собиравший их из россыпи графики 2008, был одноразовым
  инструментом миграции и ушёл вместе с россыпью (3.0.0; в истории git есть).
- Планируется VCL-половина (`SpritePack.exe`, правка спрайтов и описаний);
  логика остаётся в `Sprites.Sets`, чтобы оба исполняемых файла были тонкими.

### `tools/TitleCard/` - генератор титров для трейлера (VCL-приложение)
Рисует произвольный текст шрифтом игры в PNG. Переиспользует `Sdl2.Core`,
`Sdl2.Image`, `Sprites.Sets`, `Render.Sprites` и `Render.Font` из `Core/` по
относительному пути - открывает
`ui.mset` и просит спрайт `fonty`, тем же путём, каким ходит игра.
- **`TitleCard.dpr`** - VCL-бутстрап.
- **`TitleCard.Layout.pas`** (~355 строк) - чистая математика раскладки.
  Константы: измеренные метрики "чернил" шрифта (`InkTopRatio`,
  `CapHeightRatio`). Записи: `TCardGeometry` (размер, поля, оптический центр
  0.45, межстрочный интервал), `TCardScale` (smFitInteger/FitFree/Explicit +
  фабрики), `TPlacedLine`, `TCardLayout` (высота ячейки, строки, лимит символов,
  запросы переполнения). Функции: `BuildCardLayout`, `WrapCardText` (аварийный
  перенос по словам), `SplitCards` (пакетный файл, деление по пустым строкам),
  хелперы геометрии.
- **`TitleCard.Renderer.pas`** (~165 строк) - **`TCardRenderer`**: скрытое окно
  SDL плюс target-текстура, рисует раскладку, `RenderCard -> TBytes` (RGBA сверху
  вниз) через `SDL_RenderReadPixels`. `TCardBackground` = (cbTransparent,
  cbBlack).
- **`TitleCard.Config.pas`** (~170 строк) - запись **`TTitleCardConfig`** (путь
  к набору, имя спрайта шрифта, драйвер рендера, геометрия, шаги масштаба,
  пакетный шаблон, единый масштаб пакета), загрузка и сохранение ini,
  `ResolveSpriteSet` (поднимается
  на шесть папок вверх в поисках набора).
- **`TitleCard.Main.pas`** (~425 строк) - **`TMainForm`** (VCL): мемо,
  комбо-боксы соотношения сторон и масштаба, поля в процентах для отступа /
  оптического центра / межстрочного интервала, флажки чёрного фона,
  аварийного переноса и одного масштаба на пакет, живой предпросмотр,
  одиночное сохранение и пакетный рендер.
- **`Image.Png.pas`** (~190 строк) - свободная функция `SavePngRgba`,
  рукописный писатель PNG.

### `tools/bmp2png/convert.py`
Разовая миграция BMP->PNG с зашитым правилом color key (чистый чёрный, плюс
тонкая почти чёрная кайма и ровные почти чёрные заливки у границы ->
прозрачность; задники и атласы из корня остаются непрозрачными). Оставлен для
истории; сейчас его никто не вызывает.

### `tools/Selene/` - художник карты Селены (Python)
Рисует живую антилуну для глобуса меню по его же `moonmap`; игра результат
пока не читает. numpy + scipy + pillow.
- **`extract_moonmap.py`** - достаёт `moonmap` из `ui.mset`.
- **`paint_selene.py`** - поверхность + маска воды, и (`clouds`) слой облаков;
  моря по тёмному альбедо, цвет от модели климата, запечённый рельеф, реки.
  Под сидом: тот же вход даёт ту же планету бит в бит.
- **`preview_globe.py`** - глобус в "фото"-свете (блик, дымка у лимба,
  терминатор, тени облаков) - эталон для Селены в меню (попиксельный
  предрасчёт, как `Render.Globe` считает свою тень).
- **`selene_lib.py`** - шум на сфере, фильтры с замыканием по долготе,
  трассировщик рек.
- **`out/`** - утверждённые карты (2048x1024) и превью.

## Данные времени выполнения (`bin\`)

### `config.json` (крошечный)
Дефолты поставки: `window` (width/height/fullscreen/vsync/fpsCap) + `game`
(tickRate, идентификатор сложности, идентификатор языка). Читается
`Game.Config`, игра его не пишет.

Слой игрока, `%APPDATA%\Moon2D\settings.json`, той же формы, но держит только
тронутые игроком ключи (сложность, язык, полный экран - или что вписано
руками) и перекрывает config.json по ключам. Живёт вне папки игры: не в
репозитории, не в релизе, переживает распаковку новой версии поверх старой.

### `monsters.json` (~12 КБ)
Ключи: `version`, `comment`, `defaults` (bound, spritesToDeath, animFreq, score,
dangerous - наследуются монстрами), массив `monsters`. 15 идентификаторов:
`gravel`, `gravelFemale`, `winter`, `zombieShooter`, `betoner`, `platform`,
`tank`, `mount`, `barrel`, `medkit`, `weaponShotgun`, `weaponGrenade`,
`weapon3`, `weapon4`, `boss1`. Разбирается `TMonsterRegistry` в `TMonsterDef`
(полный лист полей см. в Monsters.Defs выше). У девяти из пятнадцати нет
`spriteList` - он приходит из расстановки в уровне. `explosion` называет
вид смерти: `barrel` (бочка), `machine` (танк, платформа), `boss`
(`boss1`); у крепления нет - оно взрывается внутри стены. `disc` (только
`boss1`) рисует живого монстра вращающимся диском из слоёв набора вместо
кадров `alive`: `set`, `side`, `muzzle`, `spin`, `irisReach`, `wearFull` -
см. `TDiscDef`.

### `level1.json` (~60 КБ) / `level2.json` (~20 КБ)
Единый формат уровня, разбирается `TLevel`. Ключи: `version`, `id`,
`title`/`titleEn`, `assetsDir`, **`spriteSets`** (наборы окружения в порядке разрешения),
**`objectSets`** (необязательно: общий арт объектов, ищется после
собственного набора объектов уровня, например `["sky"]`), `music`,
`legacyTrailing` (артефакт миграции, чистка не сделана),
`grid` (16x12), `backgrounds` (fromScreen + image + необязательный `tint` -
три процента), `objects` (необязательно: sprite, screen, x, y, width в
единицах экрана, необязательные `tint` и `tag`), `dynamics` (необязательно:
`kind` (beacon / smoke / globe), `screen`, `screens` [первый, последний]
или `parent` - тег статического объекта или монстра -, `x`, `y`, необязательные `tint`, `tag`, `layer`,
`intensity`, `turns` (под вращающимся родителем), дальше свойства вида -
см. `Levels.Dynamics`),
`tilePalette` (имена
спрайтов в файловом написании 2008 - `level1\doom1.png`, `base1.png` - или
квалифицированные `набор:имя`, когда два объявленных набора делят имя;
индекс N в тайлах -> palette[N-1]), `tiles` (`encoding` "csv-rows" и
`emptyValue` - справочные, не читаются; `note`; `screens` - объект на
экран: `screen`, `rows` (12 строк по 16 индексов палитры через запятую) и
`collision` (12 строк по 16 символов '0'/'1', 1 = твёрдое - сетка, которую
читает `SolidAt`)), `entities` (расстановки:
monsterId, screen, x, y, spriteList, необязательные грейды `difficulty`
(разбираются, оба уровня ими не пользуются),
`overrides` (direction / speed / lives / canShoot), `triggers` -
сообщения/подсказки/changeMusic/heroX-heroY/gravelBoss (квота волны по
сложности), необязательный `tag` для событий и динамики; `secret` у одной
аптечки уровня 1 - данные, которые пока никто не читает), `events` (у
каждого: `id`, `screen`, `when` = enterScreen | allDead / enraged + `tag` |
livesBelow + `tag` + `lives`, необязательный `delay` в тиках, `then` =
список объектов `action` - bigMessage/smallMessage/hint с `text`/`textEn`,
music с `file`, intensity с `target`/`value`/`ticks`, sun с
`target`/`value` (градусы)/`ticks`; подсказка медлаба, `labHint`, - самый
простой пример),
`introText`/`introTextEn`.
- level1: 17 экранов, 145 сущностей, палитра из 156 тайлов, 4 фона - ночь
  (1-7), предрассветный час (8-11), `_black` для целиком замощённых экранов
  лаборатории 12-13, восход (14-17); наборы
  `brickwork mine-structure facility conveyor mining-rig railway mine-walls
  cargo mine-interior`. Объекты: корабль на экране 1 (вместо шаттла 2008),
  разбитый спутник в небе 14-17, теги `ship` и `satellite`. Динамика:
  Земля (`globe`) в небе экранов 1-17 - на
  экранах лаборатории 12-13 её закрывают тайлы - (тег `earth`, в (392, 82), 38 поперёк, к Луне
  Африка и Европа, ночная карта `earth-night`, солнце стартует с -40 - освещены три четверти слева), синий
  маячок с двойной вспышкой на киле корабля, красный барахлящий (faulty) с
  лучами старбёрста на антенне спутника, три порывистые утечки газа из
  пробоины спутника и из сломанного узла кольца (вакуум: без подъёма, почти
  без сопротивления), два дыма на боссе (тег `boss`; `bossSmoke`,
  `bossBurn` с жаром, передний слой, интенсивность 0), четыре лампы на
  диске босса (`turns`, передний слой, в двух гнёздах арта обода: синяя
  пульсирующая пара `bossLamp` и красная вспыхивающая пара `bossLampRage`
  с интенсивностью 0; ореол 10 поперёк и лучи старбёрста по 24 единицы - у
  спутника 36, - выходящие за обод: на светлом диске голое свечение не
  читается). События: рассвет -
  привязан к экранам: на входе в экран N (`dawn1`..`dawn17`) солнце за 20
  секунд идёт к -40 + 100 * N / 17: в начале освещены три четверти, к
  экрану 7 половина, на последнем экране серп, ночная сторона в огнях
  городов;
  сам восход нарисован на задниках 14-17. Экран 12: `labHint` - allDead по
  четырём телам `labGuard` (два танка, самка грейвела, бетонер), через 33
  тика подсказка медлаба печатается в терминале. Экран 17:
  livesBelow 150 - bossSmoke до 60%; enraged - bossSmoke гаснет, и
  (`bossRageLamps`) синие лампы гаснут, красные разгораются за 20 тиков;
  livesBelow 30 - bossSmoke и bossBurn до 100%.
- level2: 9 экранов, 38 сущностей, палитра из 35 тайлов, 4 фона - день (1),
  край обрыва (2), скала (3-5), та же скала темнее (6-9); наборы
  `moon-surface machinery facility common mine-interior`. Объект: спутник на
  экране 1, чуть ярче (день), тег `satellite`; Земля на экране 1, как её
  оставил уровень 1, серп тоньше (солнце 70, без событий; весь арт объектов
  уровня - общий, набора
  level2-objects нет); его лампа `dying` - тусклое
  быстрое мельтешение, садится батарейка, и осталась одна утечка - изредка
  клуб (`flow` puffs). Здесь живёт испытание
  грейвелов (экран 9: триггер `gravelBoss`, квота 75/125/200 по сложности,
  под `boss2.ogg`) - монстра-босса нет, - и на этом кампания оригинала
  кончается.

### `sprites\*.mset` (35 наборов)
- **Герой и оружие**: `hero` (последовательности walk/death/henshin),
  `weapon` (кадры оружия в руках, пули, прицел), `weapon1`-`weapon4`
  (подбираемое).
- **Сущности**: `gravel`, `gravel2`, `vinter`, `shoot1`, `betoner`, `barrel`,
  `medic`, `krep`, `platform`, `tank`, `boss1` - на них ссылается `spriteList`
  расстановки, всё ещё написанием `<основа>.mns`.
- **Слои диска**: `boss1-disc` (`rim`, `rimDamaged`, `core`, `coreDamaged`,
  `iris`, `gloss`; каждый 144x144 - 4 px на единицу экрана, квадрат в 36
  единиц, - каждый слой отцентрован по оси вращения, прозрачные пиксели
  залиты цветом кромки) - назван в `disc.set` в monsters.json, рисуется
  `Monsters.Disc`. `boss1` держит восемь кадров `alive` только ради
  контракта `TAnimSet`; его кадры `death` играют по-прежнему.
- **Тайловые темы**: `brickwork`, `cargo`, `common`, `conveyor`, `facility`,
  `machinery`, `mine-interior`, `mine-structure`, `mine-walls`, `mining-rig`,
  `moon-surface`, `railway` - сгруппированы по предмету, а не по уровню, потому
  что уровни делят тайлы.
- **Задники**: `level1-backdrops`, `level2-backdrops` - находятся по соглашению
  `<assetsDir>-backdrops`, в `spriteSets` не объявляются никогда. С 3.0.11 -
  HD: 1440x1080 (4:3, игровое поле экрана 1080p один в один), рисуются с
  линейным фильтром и тинтом смены; `_black` остаётся заливкой 512x512.
- **Объекты**: `level1-objects` (`ship`) - соглашение `<assetsDir>-objects`,
  не объявляется, необязателен (у уровня 2 его нет). Общий: `sky`
  (`earth`, `earth-night`, `satellite`), оба уровня объявляют его в
  `objectSets`. Корабль и спутник нарисованы в плотности задника (1440 px на
  512 единиц), прозрачные пиксели залиты цветом края, чтобы линейный фильтр
  не оставлял тёмной каймы; `earth` и `earth-night` - равнопромежуточные
  карты глобуса 1024x512 для `Render.Globe`.
- **Интерфейс**: `ui` - `sky` (туманность 16:9), `moonmap` (лунная
  поверхность 2048x1024), `logo` (одни буквы), флаги языков (240x160) и
  атласы `font`/`fontx`/`fonty` плюс `fonty-2008` (оригинальный атлас
  448x448, сохранён, на него никто не ссылается). Звёзды, ореол и угли
  генерируются.

### `lang/en.json` / `lang/ru.json` (~2-3 КБ)
Плоские словари ключ->строка для текстов интерфейса и игры (все ключи `S*` из
`Localization.pas`): тикеры, серии, хеншин и бонусы, финальный экран, полный
словарь меню. Контента уровней и монстров здесь НЕТ - он локализован на месте, в
JSON уровней и монстров, по схеме "базовое поле + сосед `En`".

### `sounds/` (19 WAV) и `music/` (OGG)
Одиночные звуки прогреваются на старте и громко падают, если файла нет;
музыка грузится мягко. Треки, названные кодом: `moon.ogg` (меню,
`MenuMusicFile`), `win.ogg` (`VictoryMusicFile`). Данными:
`moon_surface.ogg` (уровень 1), `underground.ogg`, `moon_surface2.ogg`,
`boss1.ogg`, `boss1b.ogg` (`rageMusic` босса), `hallu.ogg` (уровень 2),
`under01.ogg`, `boss2.ogg`. Десять файлов OGG, все в деле.
